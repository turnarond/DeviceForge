# DeviceForge 接口参考

## IProtocolAdapter — 协议适配器接口

所有网络协议的抽象基类，位于 `src/adapter/IProtocolAdapter.h`。

```cpp
class IProtocolAdapter {
public:
    virtual std::string protocolId() const = 0;           // "ftp" / "telnet" / "ssh"
    virtual bool connect(const DeviceInfo&, const AuthInfo&) = 0;
    virtual void disconnect() = 0;
    virtual bool isConnected() const = 0;
    virtual std::string lastError() const = 0;
    virtual std::future<Response> request(const Request&) = 0;      // 请求-响应
    virtual void subscribe(const Request&, StreamCallback) = 0;     // 流模式
    virtual ProtocolCapability capability() const = 0;
};
```

### 添加新协议适配器

1. 创建类继承 `IProtocolAdapter`，实现所有纯虚方法
2. 在 `main.cpp` 中注册工厂：
```cpp
ProtocolRegistry::instance()->registerFactory("ssh",
    []() { return std::make_shared<SshAdapter>(); });
```

## IDeployable — 可选部署能力接口

位于 `src/adapter/IDeployable.h`。**可选部署能力**：协议适配器实现此接口即成为批量部署通道。部署循环（FtpDeployBackend）通过 `dynamic_cast` 探测该接口，与协议无关地执行上传/清空/进度/取消。目前由 FtpAdapter、SshAdapter 实现。

```cpp
class IDeployable {
public:
    virtual ~IDeployable() = default;

    // 上传单个文件到远程路径（remotePath 含文件名）
    virtual bool uploadFile(const std::string& localPath, const std::string& remotePath) = 0;
    // 递归上传整个目录（目录本身作为远程子目录创建）
    virtual bool uploadFolder(const std::string& localPath, const std::string& remotePath) = 0;
    // 清空远程目录内容（保留目录本身）
    virtual bool clearRemoteDirectory(const std::string& remotePath) = 0;
    // 进度回调：0-100 整数百分比
    virtual void setProgressCallback(std::function<void(int)> cb) = 0;
    // 取消标志：部署循环设置后，传输在每文件/每块前检查并中止
    virtual void setCancelFlag(std::atomic<bool>* flag) = 0;
};
```

`uploadFolder` 为**预留接口**：生产链路当前无调用方——批量部署与任务模板一律经可靠传输内核以 `uploadFile` 单文件通道交付；文件夹支持在**入口层**目录展开实现（口径见上节 `DeployJob` 双路径与用户手册文件部署节）。

## FtpAdapter — FTP/FTPS 适配器

## 可靠传输内核接口（v2.9）

位于 `src/transfer/`，属于内部业务接口，不改变 `IProtocolAdapter` 与 `IDeployable` 的 ABI。

`TransferTask` 由设备、协议、凭证身份、代际和 `TransferItemRequest` 文件项目组成；凭证密码不放入任务对象。每个项目包含本地路径、远程路径、方向（`Upload`/`Download`）和覆盖策略（`Overwrite`/`Skip`）。

`ITransferChannel` 提供 `connect`、`reconnect`、`upload`、`download`、`stat`、`rename`、`remove`、进度/取消回调和 `lastError`。`AdapterTransferChannel` 映射 FTP/FTPS 与 SFTP，`LocalTransferChannel` 服务本地双栏复制/移动；能力通过 `TransferCapabilities` 显式声明。

v2.15 波2 扩展：`ITransferChannel` 接口**末尾**追加可选虚函数 `makeDirectory(remotePath)`——默认实现返回 false（不支持），旧通道实现零改动即向前兼容（ABI 纪律）。语义为**单层**创建：仅创建路径最后一段，父目录不存在即失败；逐级编排收敛在 `TransferExecutor` 上传前的父目录确保步（目标**不存在**时才执行——目标存在即证明父存在，既有通道 stat 增量零漂移；stat 自最浅缺失层起判定、序贯创建；建目录报失败后复检该层，存在则继续——闭合连接瞬断被收口成确定性红的窗口）。确保步逐级拆解**仅按正斜杠 `/` 分段**（远端为 POSIX 路径口径，反斜杠是合法文件名字符，分段口径与 `AdapterTransferChannel::parentPath` 一致——见 `TransferExecutor.cpp` 中 `remoteDirectoryLevels` 处代码注释，带盘符的 Windows 风格远端路径不在该步支持声明范围）；无 `makeDirectory` 能力位的通道遇父目录缺失为**确定性 `Unsupported` 失败**（文案「远端目标父目录不存在且通道不支持自动创建」，且绝不触碰 `makeDirectory`）。`TransferCapabilities` 末尾增 `makeDirectory` 能力位（默认 false，既有五项聚合初始化零改动）。通道实现口径：`FtpAdapter::makeDirectory` 发单层 MKD，SylixOS 三禁逐条核对（QUOTE 用根 URL+绝对路径、单层 MKD 不依赖服务端多级能力、`CURLOPT_FTP_USE_EPSV=0` 与 `CURLFTPMETHOD_MULTICWD` 自 #59 起由 `setupCommonOpts` 单源提供——勿回退也勿在腿内行内复写，见下节「SylixOS 三禁的单源保证」）；`SshAdapter` 走 `sftpMakeDirectory`（libssh2 单层 mkdir）；`LocalTransferChannel` 为真盘单层 mkdir（父缺失即失败，与协议通道同一口径，不做全路径 mkpath——逐级编排归执行器，避免两层"半递归"叠加）。

`TransferExecutor::execute()` 返回 `TransferItemResult`：`attempts` 记录实际尝试次数，`skipped` 表示跳过，`atomicCommitSucceeded` 表示不可逆提交完成，`deliverySucceeded` 表示目标已校验交付，`sourceRemoved` 表示 F6 已删除源，`nonAtomic` 表示提交降级。`TransferScheduler::submit/cancel/shutdown` 提供任务提交、取消和收口，按设备键串行、跨设备并行。

批量部署事务 `DeployJob` 为双路径口径（v2.15 波2 任务9）：随 `files` 传入与其同长的 `entryRemotePaths` 平行向量即**显式条目模式**——本地条目已由入口装配纯头 `deployentry::build`（单发/编辑器/保存为模板三入口共用）按点击时刻磁盘实况展开为普通文件与镜像远端全路径，Job 不派生 basename、不做目录遍历、**刻意跳过自身 mkdir 环**，远端子目录全部交由执行器侧父目录确保步创建。缘由：目录镜像映射收敛入口单源，Job 不再是第二处目录口径，杜绝两处漂移分叉（v2.14 的 FTP/SFTP 目录落点协议不对称即出自 Job 内 legacy 遍历）。远端向量为空即 v2.14 legacy 扁平路径（basename 派生 + Job 内目录展开、无条目数上限），仅直接组装 Params 的历史调用方/测试可达，新调用方勿依赖。显式条目模式路径由 `tst_deploy_loop` 单发镜像用例与真盘目录树环回集成用例钉住；v2.14 legacy 的 Job 内目录展开腿由 `tests/deploy/tst_deploy_runner.cpp` 回归契约钉住（该可达性口径与 `DeployJob.cpp` 展开分支处代码注释一致）。

### SylixOS 三禁的单源保证（GitHub #59）

`FtpAdapter.cpp` 的每条会做 FTP I/O 的 libcurl 腿（`connect`/`uploadFile`/`downloadFile`/
`readFileToMemory`/`writeFileFromMemory`/`listDirectory`/`listDirectoryParsed`/`deleteFile`/
`deleteDirectory`/`renameFile`/`makeDirectory` 共 11 条）都**必须先调用内部装配函数
`FtpAdapter::Impl::setupCommonOpts`**，再由各腿补自己的专有项（读写回调、`INFILESIZE_LARGE`、
`FTP_CREATE_MISSING_DIRS`、`LOW_SPEED_*`、进度取消钩子、QUOTE 命令表等）。三禁的保证位置：

| 禁令 | 内容 | 单源位置 |
|---|---|---|
| ① | `CURLOPT_FTP_USE_EPSV = 0`（强制 PASV） | `setupCommonOpts` |
| ② | `CURLOPT_FTP_FILEMETHOD = CURLFTPMETHOD_MULTICWD`（逐级 CWD） | `setupCommonOpts` |
| ③ | QUOTE 命令用根 URL（`buildUrl("/")`）+ 首斜杠绝对路径 | 四条 QUOTE 腿各自的命令装配段（`deleteFile`/`deleteDirectory`/`renameFile`/`makeDirectory`） |

**禁止在任何腿内行内 `curl_easy_setopt(curl, CURLOPT_FTP_USE_EPSV, …)` 或
`CURLOPT_FTP_FILEMETHOD, …`**——行内重复正是 #59 的缺陷形态（散在四处、另四处漏设，两处口径分叉）。
新增 FTP 腿时同样禁止绕过 `setupCommonOpts` 自建选项序列。

`setupCommonOpts` 的超时口径（非三禁项，勿顺手"改进"）：`timeoutSec` 默认 30、
`connectTimeoutSec` 默认 10，供控制命令类腿（连接/列目录/删除/改名/建目录）使用；
批量传输腿（上传/下载/内存读写）传 `Impl::kBulkTransferTimeoutSec = 0`（不设总时长上限）与
`Impl::kBulkTransferConnectTimeoutSec = 300`（libcurl 默认连接超时），二者与这些腿并入装配处
之前的有效选项集逐字等价——工业慢链路的长传输不受人为上限约束的原语义（issue #20）不变。

回归钉桩：`tools/devtools/ftpguard.py` 是这条不变式的静态守卫（`python tools/devtools/ftpguard.py`
退出码 0=干净 / 1=命中违规 / 2=目标缺失 / 3=零证据），并由 `tools/tests/test_ftpguard.py` 的
真码闸门用例纳入 CI（`ci.yml` 与 `release-validation.yml` 都跑 `python -m unittest discover -s tools/tests`）。
守卫对禁令③取**窄口径**结构判据（QUOTE 腿必须用根 URL 字面量、命令串必须见过首斜杠绝对化惯用法），
其做不到的事（死代码、跨文件供能、运行期取值、路径语义对错）在该工具 docstring 与
`tools/tests/test_ftpguard.py` 的 `NegativeControlTest` 里如实登记，不得当成全量覆盖。

## OpcUaAdapter — OPC UA 客户端适配器

位于 `src/adapter/OpcUaAdapter.h`。基于 open62541 v1.5.5，OPC UA 客户端。首期 None 安全策略 + 匿名认证。

```cpp
class OpcUaAdapter : public IProtocolAdapter {
public:
    // IProtocolAdapter 实现
    std::string protocolId() const override { return "opcua"; }
    bool connect(const DeviceInfo&, const AuthInfo&) override;  // device.ip 为完整 opc.tcp:// URL 或 host
    void disconnect() override;

    // OPC UA 特有操作（批量读/写 + 浏览）
    QVariantMap readNodes(const QStringList& nodeIds);                 // NodeId → 值（QVariant）
    QMap<QString, QString> writeNodes(const QStringList& nodeIds,      // 每节点返回状态码字符串
                                      const QVariantList& values);
    QString browseRoot();                                              // Objects 节点直接子节点，JSON

    // DataChange 订阅（MonitoredItem）
    using DataChangeCb = std::function<void(const QString& nodeId, const QVariant& value,
                                            quint64 timestampMs, const QString& quality)>;
    quint32 subscribeDataChange(const QStringList& nodeIds, DataChangeCb cb);  // 返回 subscriptionId(0=失败)
    void unsubscribeAll();
    void runIterate(int timeoutMs);   // 驱动 open62541 事件循环，派发 DataChange 回调（由 Backend svc 线程调用）
};
```

> **NodeId 格式**：`ns=<命名空间>;i=<整型>` 或 `ns=<命名空间>;s=<字符串>`，内部用 `UA_NodeId_parse` 解析。
>
> **线程安全**：open62541 以 `UA_MULTITHREADING=100` 编译（内部已加锁，`UA_THREADSAFE` 函数可跨线程并发）。`OpcUaAdapter` 的 `recursive_mutex` 保护适配器自身状态（`m_subscriptionId`/`m_monContexts` 等）；`subscribeDataChange` 的回调在 `runIterate`（svc 线程）内触发，使用方需将 UI 更新 marshal 到 GUI 线程。

## DeviceBusWidget — 设备总线

位于 `src/ui/DeviceBusWidget.h`。设备栏第 1 行的宿主：**只显示已选中的设备（chips）**，其余设备收进「设备 ▾」`QMenu` 分组入口（行为见《用户手册》设备总线与设备档案一节）。

```cpp
class DeviceBusWidget : public QWidget {
    Q_OBJECT
public:
    void addDevice(const DeviceInfo& device, bool persist = true);
    void removeDevice(const QString& ip);
    void setRegistry(DeviceRegistry* registry);          // 接入档案注册表；未接入时保持旧 ip:port 行为
    std::vector<DeviceInfo> selectedDevices() const;     // 按显式选中集合取，一台一条
    std::vector<DeviceProfile> selectedDeviceProfiles() const;
    std::vector<DeviceInfo> allDevices() const;           // 恒为全集（见下硬线）
    QSet<QString> selectedIds() const;                    // 选中真源的只读视图
    void selectAllVisible();   // 「全选可见 N 台」：只作用当前过滤可见集
    void clearSelection();     // 「清空选择」：清全量已选，不受可见集限制
    void setOnlineStatus(const QString& ip, bool online); // 有钩子无数据源：全仓零调用方，勿依赖
    QString user() const;
    QString password() const;
    QList<QVariantMap> historyDevices() const;            // ConfigStore device.list 缓存
signals:
    void deviceSelectionChanged();
    void credentialsChanged(const QString& user, const QString& password);
    void deviceProfileEdited(const DeviceProfile& profile);
    void openDeviceRequested(const DeviceProfile& profile);   // 纯加法信号
};
```

**契约要点**：

- **选中真源是显式 id 集合**（`QSet<QString> m_selectedIds`，键式单源 `makeSelectionKey`：`deviceId` 优先，无持久 id 的旧行退化为 ip 键），不再靠 `m_devices[i]`↔`m_pills[i]` 位置配对推断。因此**按设备去重由结构保证**：一台带 N 个标签的设备在 N 个子菜单里各出现一次，选中集合里仍只有一个键，`selectedDevices()`/`selectedDeviceProfiles()` 各返回**一条**，执行目标集不会翻倍。
- **`allDevices()` 恒为全量**（硬线）：chips 只是"已选"的视图，过滤、菜单展开状态、折叠与 `+M 台` 收纳一律只切可见性、不从数据集合删条目。批量命令页（`TelnetWidget`）读的就是它，目标集不随设备栏视图变化。
- `user()`/`password()` 与选中态解耦（凭据输入框语义不变）。
- **`openDeviceRequested(const DeviceProfile&)`**：双击 chip 名称主体、或右键菜单首项「打开这台设备」时发射。载荷是档案——旧 `ip:port` 胶囊经 `fromDeviceInfo` 现成合成，故无需第二条通道。本组件**只发射、不切页**；切页与"把部署页下拉切到该 ip"的编排归 `DeviceForge::openDeviceAt`。**移出选择**走 chip 尾部「×」命中区（键盘空格/回车亦按移出），**主体单击不改变选择**。
- 重建走 `blockSignals(true)` 窗口 + 末尾单次广播：菜单里连勾多台只发一次 `deviceSelectionChanged()`。

## DeviceBusGroups / DeviceOpenRouter — 设备栏的两个纯逻辑头

两个头都**无 QWidget、无 ConfigStore 依赖**，可被最小测试目标直接 include（参照 `FolderExpand.h`/`DeployEntryBuilder.h` 的纯头模式），由 `tests/device/tst_device_bus_groups.cpp` 直测。

**`src/device/DeviceBusGroups.h`（namespace `devicebus`）＝分组与标签规范化的唯一真源**。放数据层而非 ui 层：`src/device/DeviceRegistry.cpp` 与 `src/task/TaskCenterWidget.cpp` 都要消费它，AGENTS.md 的依赖方向禁止低层反向 include `ui/`。

```cpp
}
```

- `segments()` 是唯一分类真源：一台多标签设备在 N 个段各出现一次；规范化后无标签只进「未分组」；标签段按 `tag` 升序（**区分大小写**）、「未分组」永远最后且空段不进结果；`filterText` 非空时段内只留命中项而 `total` 仍是不过滤的成员总数（菜单显示 `组名 命中数/总数`）；0 命中段不进结果。
- **成员载体是 `QList<int> profileIndexes`（不是 deviceId 串）**：下标即真源，无 id 可查、无重名可混（空 `deviceId` 的 legacy 合成档案若按 id 反查会错认成前一台）。**调用方必须把同一份 `profiles` 向量交给 `segments()`**，两份不同快照会静默错位。
- `normalizeTag` 是模板圈选与存库前的单源口径：`TaskCenterWidget::resolveTargets` 与 `DeviceRegistry::normalize` 都调它；`DeviceProfileCodec` 读侧**不调**（避免第二条真源）。范围只到"去首尾空白 + 空/纯分隔符判空"，不改大小写、不折叠内部空格、不做全半角转换。

**`src/ui/DeviceOpenRouter.h`（namespace `deviceopen`）＝档案→目标工具页与选中键的判定**，留 UI 层：`Page` 枚举是"有哪些工具页"的 UI 知识，消费方只有最高层的 `src/app/DeviceForge.cpp`。

```cpp
namespace deviceopen {
enum class Page { FtpDeploy, BatchCommand, Modbus, OpcUa, None };
struct Route { Page page; QString protocol; QString ip; int port; QString statusHint; };
Route routeTo(const DeviceProfile& profile);   // 取首个"协议可解析且 ip 非空"的端点
Page pageFor(const QString& protocol);         // ftp/ftps/sftp→FtpDeploy, telnet/ssh→BatchCommand, modbus→Modbus, opcua→OpcUa
}
```

- `Route` **必须携带命中端点的 ip/port**：部署页设备下拉的条目键就是 ip 文本，路由与选中同源才不会"路由按 A 端点、下拉选 B 端点"。
- 扫描口径：逐个端点扫描，遇空 ip 或协议不认识的端点**跳过继续找下一个**；整条档案无可用端点才 `page = Page::None` 并给 `statusHint`「该设备没有可用的协议端点」（调用方据此**不切页**、只提示）。**协议列为空串**才按 `ftp` 兜底（旧 `device.list` 合成行的口径）；非空但不认识的协议走上面的扫描口径，不是兜底。
- `opcua` 映射当前**不可达**（档案端点协议白名单 `devicebus::editableEndpointProtocols()` 不含 opcua），仅纯头级覆盖，待 OPC UA 纳入统一设备/凭据体系后转可达。

**消费方一览**：`segments()`/`matchesFilter()` 由 `DeviceBusWidget` 的分组菜单与搜索框消费；`normalizeTag()` 另由 `DeviceRegistry`（存库前）与 `TaskCenterWidget`（模板圈选）消费；`routeTo()` 由 `DeviceForge::openDeviceAt` 消费——它据 `Route.page` 切 `QStackedWidget`，**仅部署页另有"选中这台"的一步**：

```cpp
// src/tools/FtpDeployTool/FtpDeployWidget.h
bool selectDeviceByIp(const QString& ip);
```

命中→把设备下拉切到该 ip 并**走用户同一条 `currentTextChanged` 路径**（右面板源同步 + `onRefreshRemote()` 刷新，**不** `blockSignals`——那才是"打开即就绪"的语义；`blockSignals` 会把动作降级成"打开只换个字"）；未命中或无下拉→返回 `false` 且不动当前选择。批量命令页没有"当前设备"概念（该页只读 `allDevices()` 与凭据），MODBUS 页未接设备总线，二者被 `openDeviceAt` 跳过去时**只切页**，不做任何选中动作。
