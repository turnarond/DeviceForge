# DeviceForge v2.4：一个工业设备运维工具的现代化历程

> 一个用 Qt 写的工业设备批量运维工具，v2.4 版本做了两件事：把 FTP 部署从表单变成了双栏文件管理器，把整个主窗口从 Windows 95 风格拉到了 2026 年的水平。

---

## 它是什么

DeviceForge 是一个基于 Qt 6 + C++17 的 Windows 桌面应用，用来对 PLC 设备做批量运维：FTP/FTPS 部署固件、Telnet/SSH 批量执行命令、Modbus 寄存器读写、OPC UA 客户端、WebSocket 通信、TCP/UDP 网络调试中继。

前身叫 DeployMaster，2026 年 7 月改名。和 PLCBasicConfigurator 配套，覆盖 SylixOS PLC 设备的「配置 → 部署 → 测试 → 运维」全流程。

开源，GitHub：[turnarond/DeviceForge](https://github.com/turnarond/DeviceForge)（注意：仓库名仍为 DeployMaster，CMake 项目名已改为 DeviceForge）。

---

## 为什么又造一个轮子

市面上不缺 FTP 工具。FileZilla、WinSCP、Total Commander 的 FTP 插件都是成熟产品。但它们有一个共同缺陷：**只能一対一操作**。

实际场景是这样的：一套固件需要同时部署到 5 台、10 台甚至更多的 PLC 设备上。用传统工具的做法是——连上第一台，传文件，断开；连第二台，传文件，断开……反复操作。每台设备传完后还要手动检查文件列表确认上传成功。

DeviceForge 的设计出发点就是：**一次操作，并行部署到多台设备，传完自动刷新远程目录，一眼就能确认结果**。

这是传统 FTP 工具做不到的事。

---

## v2.4 做了什么

### 1. FTP 部署从表单变成双栏文件管理器

**之前：** 一个纵向表单——选设备 → 填路径 → 弹对话框添加文件 → 点按钮部署。每次加文件都要弹 Windows 文件对话框，看不到远程目录，传完不知道到底有没有成功。

**现在：** QSplitter 双栏——左侧本地目录树（QFileSystemModel），右侧远程 FTP 目录表格（自定义 QAbstractTableModel）。直接在两侧浏览、拖拽上传、右键管理远程文件。

```
┌─ FTP 部署 ────────────────────────────────────────────────┐
│ 工具栏: [目标设备 ▾] [远程路径 /apps/___] [FTPS □] [刷新] │
├──────────────────────┬────────────────────────────────────┤
│  📁 本地文件          │  📁 远程文件 (192.168.1.100)       │
│  D:\firmware\        │  /apps/m580cn/bin/                 │
│                      │                                    │
│  📄 app.bin   1.2 MB │  📄 app.bin   1.2 MB  2026-07-20  │
│  📄 params.ini  4 KB │  📄 params.ini  4 KB  2026-06-15  │
│  📄 boot.bin  256 KB │  📄 boot.bin  256 KB  2026-03-01  │
├──────────────────────┴────────────────────────────────────┤
│ [▶ 部署到 3 台设备]  [进度]                               │
├───────────────────────────────────────────────────────────┤
│ [12:30:15] app.bin → 192.168.1.100 ✓ (1.2M, 3.2s)       │
│ [12:30:18] app.bin → 192.168.1.101 ✓ (1.2M, 3.5s)       │
│ [12:30:22] app.bin → 192.168.1.102 ✓ (1.2M, 3.1s)       │
└───────────────────────────────────────────────────────────┘
```

几个实际有用的细节：

- **拖拽上传**：从 Windows 资源管理器拖文件到右侧远程面板，直接上传
- **对比着色**：远程文件如果和本地同名，行背景标记为黄色（有差异），后续会加上精确的大小/时间对比
- **部署后自动刷新**：传完自动刷远程面板，不需要手动点刷新
- **并行部署**：多台设备同时上传，每台设备独立进度条

### 2. 布局从传统 Qt 变成左侧导航栏

**之前：** 顶部 QTabWidget 水平标签页 + 右侧远端预览面板 + 底部日志。这是 Qt 应用最经典的布局，但也最显旧。

**现在：**

```
┌──────┬───────────────────────────────────────────────┐
│  📁  │ [📡 192.168.1.100 ×] [📡 192.168.1.101 ×]    │
│ 文件 │ [👤 admin] [🔑 ****]                          │
│ 部署 ├───────────────────────────────────────────────┤
│      │                                                │
│  📝  │          工具工作区（全宽）                      │
│ 批量 │                                                │
│ 命令 │                                                │
│      │                                                │
│  🔌  ├───────────────────────────────────────────────┤
│ Web  │ 📋 全局日志                          [▲ 折叠]  │
│Socket│                                                │
└──────┴───────────────────────────────────────────────┘
```

- **左侧 72px 竖排导航栏**：图标 + 中文标签，活跃态琴色高亮，替代原来的水平标签页
- **设备栏从厚重横条变成胶囊标签**：石墨底 + 琴色选中态边框，空间省了一半
- **底部日志可折叠**：不部署时可以收起来，新日志到达时折叠条闪烁琴色提示
- **远端预览面板已移除**：FTP Tab 内的双栏远程面板完全替代了它的功能

### 3. 还有一些边角打磨

- 6 个 Tool 的独立日志区全部移除，所有消息统一走底部全局日志（通过 ToolWidget 基类的回调机制）
- FtpListParser 支持 Unix `ls -l` 和 Windows `dir` 两种 FTP LIST 格式自动检测
- RemoteFileModel 提供 5 列视图（图标/名称/大小/修改时间/权限）
- 面包屑导航支持任意层级跳转
- 右键菜单：下载、删除、重命名、新建目录、复制路径

## 技术实现

### 堆栈

| 层 | 技术 |
|----|------|
| UI | Qt 6.11.1 Widgets（不是 QML），QSS 深色主题 |
| 构建 | CMake 3.22+，Visual Studio 2022 |
| FTP | libcurl 8.20.0，FTPS 加密 |
| OPC UA | open62541 v1.5.5（单文件分发，UA_MULTITHREADING=100） |
| SSH | libssh2 |
| 配置持久化 | SQLite + Windows DPAPI 加密（ConfigStore） |
| 日志 | 自研 lwlog（控制台/文件双 appender） |

### 架构

```
Tool = ToolBackend (ServiceTask) + ToolWidget (QWidget)
         ↕ lwmsgq 消息队列解耦
统一 IProtocolAdapter 接口 + ProtocolRegistry 工厂
```

6 个 Tool（FTP / Telnet+SSH / WebSocket / Modbus / 网络中继 / OPC UA）都遵循 Backend + Widget 配对模式。ToolHost 是桥接层，但当前 Tool 直接由 DeployMaster 创建（ToolHost 的多 Tool 并发管理还在 TODO 里）。

### 关于深色主题

主题叫「琴色是动词」——核心原则就一条：琴色 #F0A030 **只用于标记"此刻可动作/此刻活跃"的信号态**，绝不用作静止边框或大面积填充。

- 结构边框一律中性石墨（#252A33 / #333B48）
- 输入框凹陷（填充比面板暗 #0E1219），按钮凸起（填充比面板亮 #232A36）
- 进度条用青绿 #40C8A0（与琴色语义区分）
- QSplitter 分隔条纯石墨无边框

这个约束是故意加的——在没有设计师的情况下，限制调色板的使用场景比追求"好看"更能保证视觉一致性。

## 诚实的限制

### 还没有的东西

- **重命名和新建远程目录**：右键菜单有这两个选项，但因为 FtpAdapter 尚未实现 RNFR/RNTO/MKD 命令，目前点击会弹出提示"后续版本支持"。
- **远程文件精确对比**：当前 RemoteFileModel 的黄色标记仅基于文件名匹配，还没有做文件大小和时间戳的精确对比（代码里留了 TODO）。
- **SCP 协议**：虽然 UI 预留过，但远端预览面板已移除，SCP 计划改为通过 FtpAdapter 扩展实现。
- **OPC UA 安全策略**：目前只支持 None 安全策略 + 匿名认证。Basic256 和证书认证在 v2.5 路线图上。
- **单元测试覆盖率低**：目前只有 6 个测试目标，覆盖了 NetRelay 录制回放、OTA 更新检查、DPAPI 加解密、ConfigStore、OPC UA 编解码。FtpAdapter、TelnetAdapter、ToolRegistry 还没写测试。
- **仅 Windows**：虽然 CMake 已就绪，但未在 Linux 上完整验证（DPAPI 加密在非 Windows 上是 no-op stub）。

### 可能会劝退的点

- 这是个 Qt Widgets 应用，不是 Electron 套壳。界面不会像网页那样花哨，交互也不是 Web 式的。
- 没有安装包。目前是 CMake 构建出 exe，自己复制到目标目录。

---

## 总结

DeviceForge v2.4 不是一个"全面碾压现有工具"的产品，而是一个在特定场景（工业 PLC 批量部署）下做对了关键差异化的工具：

1. **多设备并行部署**——传统 FTP 工具做不到
2. **双栏文件管理器**——不再需要在系统和应用之间反复切窗
3. **现代化布局**——左侧导航栏 + 可折叠日志，比传统 Qt 三段式好用

如果你也经常给 PLC 设备批量传固件、敲命令、读寄存器——可以试试。如果只是偶尔传一个文件到一台服务器，FileZilla 足够了。
