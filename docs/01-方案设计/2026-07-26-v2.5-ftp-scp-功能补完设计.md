# DeviceForge v2.5 FTP/SCP 功能补完设计

**日期**：2026-07-26
**状态**：设计中 → 待实施
**关联**：[[2026-07-25-FTP双栏重构设计]] | [[2026-07-10-SSH适配器设计]]

---

## 背景

v2.4 完成了 FTP 部署双栏重构 + 主窗口布局现代化。FTP 双栏已具备完整的本地/远程文件浏览、拖拽上传、多设备批量部署能力，但留下了几个功能缺口：

1. **远程重命名/新建目录**：右键菜单有这两个选项，但只弹出 QMessageBox "后续版本支持"，用户点击无实际效果
2. **远程文件精确对比**：RemoteFileModel 仅做文件名匹配（全标黄色），未实现 size + 时间戳的精确对比
3. **SCP/SFTP 支持**：路线图已预留，FTP 双栏只在 FTP 协议下可用，无法覆盖 Linux 嵌入式设备的文件传输需求

## 目标

补完 FTP 双栏的功能缺口，并通过 SFTP 扩展将双栏文件管理器覆盖到 FTP 和 SFTP 两种协议。

## 一、FTP 重命名 + 新建目录

### FtpAdapter 扩展

新增两个方法，复用现有 `CURLOPT_QUOTE` 模式（与 `deleteFile()` 一致）：

```cpp
// FtpAdapter.h
bool renameFile(const std::string& remotePath, const std::string& newName);
bool makeDirectory(const std::string& remotePath);
```

**实现**：
- `renameFile`: CURLOPT_QUOTE 发送两条命令：`RNFR /path/oldname` + `RNTO /path/newname`
- `makeDirectory`: CURLOPT_QUOTE 发送 `MKD /path/dirname`

路径构造规则与 `deleteFile()` 相同——自动处理前导 `/`。

### FtpDeployWidget 改动

- `onRenameRemote()`：QMessageBox 替换为实际的 `FtpAdapter::renameFile()` 异步调用，操作完成后刷新远程面板
- `onNewRemoteDir()`：同上，调用 `FtpAdapter::makeDirectory()`

无新增 UI，右键菜单行为从"待实现提示"变为实际执行。

### 安全考虑

- 重命名目标路径校验：确保 `newName` 不包含 `/` 或 `..`（防止路径穿越）
- 操作前弹确认对话框（与删除操作一致）

## 二、远程文件精确对比

### 新增 LocalFileInfo 结构

```cpp
// src/tools/FtpDeployTool/FtpFileInfo.h 补充
struct LocalFileInfo {
    std::string name;
    uint64_t    size = 0;
    std::string dateTime;  // ISO 8601，用于辅助判断
};
```

### RemoteFileModel 增强

`setLocalFilesForCompare()` 签名改为接受 `std::vector<LocalFileInfo>`：

```cpp
void setLocalFilesForCompare(const std::vector<struct LocalFileInfo>& localFiles);
```

对比逻辑：
- **绿色（已同步）**：远程文件与本地文件同名，且 size 完全一致
- **黄色（有差异）**：远程文件与本地文件同名，但 size 不同
- **无标记（远程独有）**：本地不存在同名文件

时间戳作为辅助信号（size 相同但时间不同的 → 仍然标绿，因为文件内容大概率一致；size 是最可靠的内容变化信号）。

### FtpDeployWidget 触发

在本地面板中选中文件时，遍历选中项通过 `QFileInfo(filePath)` 获取 size 和 modification time，构造 `LocalFileInfo` 列表传入 `RemoteFileModel::setLocalFilesForCompare()`，触发精确对比着色。

## 三、SshAdapter SFTP 扩展

### 协议选择

对外宣传「SCP 支持」，实际底层使用 SFTP（SSH File Transfer Protocol）。原因：纯 SCP 协议仅支持推/拉文件，无法列目录、删除、重命名——而双栏文件管理器需要全部这些操作。SFTP 是 SSH 的标准文件传输子系统，libssh2 完整支持。

### 接口

在现有 SshAdapter 上新增 SFTP 操作（现有 SSH exec channel 不变）：

```cpp
// SshAdapter.h 新增
#include "tools/FtpDeployTool/FtpFileInfo.h"  // 复用 FtpFileInfo

class SshAdapter : public IProtocolAdapter {
public:
    // --- 已有（不变）---
    // connect / disconnect / isConnected / lastError / request / subscribe / unsubscribe / capability

    // --- 新增 SFTP 文件操作 ---
    std::vector<FtpFileInfo> sftpListDirectory(const std::string& remotePath);
    bool sftpUploadFile(const std::string& localPath, const std::string& remotePath);
    bool sftpDownloadFile(const std::string& remotePath, const std::string& localPath);
    bool sftpDeleteFile(const std::string& remotePath);
    bool sftpDeleteDirectory(const std::string& remotePath);
    bool sftpRename(const std::string& oldPath, const std::string& newPath);
    bool sftpMakeDirectory(const std::string& remotePath);
    void sftpSetProgressCallback(std::function<void(int)> cb);
};
```

### libssh2 SFTP API 映射

| 操作 | libssh2 调用 | 说明 |
|------|-------------|------|
| 初始化 | `libssh2_sftp_init(session)` | 在 connect 之后调用，保存 m_sftpSession |
| 列目录 | `libssh2_sftp_opendir` → `readdir` → `closedir` | `LIBSSH2_SFTP_ATTRIBUTES` → `FtpFileInfo` |
| 上传 | `libssh2_sftp_open(WRITE\|CREAT\|TRUNC)` → `write` → `close` | 分块读写循环（8KB） |
| 下载 | `libssh2_sftp_open(READ)` → `read` → `close` | 同上 |
| 删除文件 | `libssh2_sftp_unlink` | |
| 删除目录 | `libssh2_sftp_rmdir` | 非空目录需先递归删除 |
| 重命名 | `libssh2_sftp_rename` | POSIX rename 语义 |
| 新建目录 | `libssh2_sftp_mkdir` | |
| 清理 | `libssh2_sftp_shutdown` | 在 disconnect 时调用 |

### 属性映射

SFTP 的 `LIBSSH2_SFTP_ATTRIBUTES` 直接映射到 `FtpFileInfo`（数据已在服务端结构化，无需文本解析）：

| ATTRIBUTES 字段 | FtpFileInfo 字段 | 转换 |
|----------------|-----------------|------|
| `.name` | `name` | 直接 |
| `.flags & LIBSSH2_SFTP_S_IFDIR` | `isDir` | bool |
| `.filesize` | `size` | 直接 |
| `.permissions` | `permissions` | 八进制 → `rwx` 字符串 |
| `.mtime` | `dateTime` | Unix ts → ISO 8601 |

### 与 FtpAdapter 的接口协议统一

FtpAdapter 和 SshAdapter 都操作 `FtpFileInfo`，但接口格式不一致（FtpAdapter 用 `uploadFile(local, remote)`，SshAdapter 用 `sftpUploadFile(local, remote)` 加 `sftp` 前缀）。

v2.5 不做强制统一——保持各 Adapter 独立接口，由 FtpDeployWidget 调用方通过 `dynamic_cast` 判断类型后调用对应方法。接口统一（如统一的 `IFileSystemAdapter` 接口）留到后续重构。

## 四、FtpDeployWidget 协议切换

### 工具栏新增协议选择

```
[协议: FTP ▾] [目标设备 ▾] [远程路径 /___] [刷新] [端口: 21]
```

协议下拉框：`FTP` / `SFTP`

### 切换行为

1. 远程面板清空（`RemoteFileModel::clear()`）
2. 端口自动切换：FTP→21，SFTP→22
3. 面包屑重置为 `/`
4. 后续所有远程操作（列目录/上传/删除/重命名/新建目录/下载）通过当前协议的 Adapter 执行

### 异步操作分流

在 `onRefreshRemote` / `onDeleteRemote` / `onDownloadRemote` 等异步方法中：

```cpp
if (m_protocolCombo->currentText() == "SFTP") {
    auto adapter = ProtocolRegistry::instance()->create("ssh");
    auto* ssh = dynamic_cast<SshAdapter*>(adapter.get());
    // 调用 ssh->sftpXxx()
} else {
    auto adapter = ProtocolRegistry::instance()->create("ftp");
    auto* ftp = dynamic_cast<FtpAdapter*>(adapter.get());
    // 调用 ftp->xxx()
}
```

拖拽上传同理。

## 七、风险与限制

| 风险 | 缓解 |
|------|------|
| libssh2 SFTP 大文件传输可能阻塞 UI 线程 | 所有操作通过 `QtConcurrent::run` 异步执行，与 FTP 一致 |
| SFTP 列目录返回 . 和 .. | 过滤代码与 FtpListParser 一致 |
| SFTP 服务器不支持某些操作 | 返回错误信息通过 appendLog 输出，不崩溃 |
| SFTP 连接超时 | 复用 SshAdapter 现有超时配置 |
