# DeviceForge 界面视觉语言重构设计（Instrument 精密仪器）

- **日期**：2026-11-02
- **状态**：待评审（SDD 阶段 1 门禁；评审通过后进入实施计划）
- **版本目标**：v2.17 候选（版本边界待发布时定）
- **需求来源**：用户反馈——当前界面「内容乱、复杂、颜色单一的白、设计感不足、不够现代化」
- **关联**：本波只做**视觉语言换皮（第一步）**；**布局/信息架构重构（第二步）**留后续版本，本设计仅列方向

---

## 1. 意图与为什么

用户日常打开 DeviceForge（亮色主题）的感受：功能全部铺在眼前、颜色只有白与灰、没有视觉层次与引导。当前亮色主题是「白底 + 浅灰边框 + 灰字」的单层灰阶，深色主题是既有「琴色是动词」体系。

本次目标：用一套**精密仪器（Instrument）视觉语言**替换现有视觉层——冷灰画布 + 纯白面板 + 深青信号色 + 等宽数据字 + 明度阶梯分层，解决「单一的白」与「不像成品」，同时**不改变任何功能与布局结构**（低风险、可回滚）。「乱/复杂」的结构问题由第二步布局重构解决；先换视觉，让「哪里乱」看得更清楚。

## 2. 目标 / 非目标 / 反目标

**目标**
- 亮色主题（主推，日常使用）全量重做为 Instrument 浅色
- 深色主题同步重做为「深色 Instrument」（同体系、明度反转），双主题语义一致
- 信号色语义从「琴色」切换为「青色」，并重写语义规则（见 §5.5）
- 视觉层覆盖全部界面：主窗口、7 个 Tool 页、任务中心、设置页、对话框、状态栏、日志
- 更新像素测试与文档中的主题描述

**非目标（本波不做）**
- 不改布局结构、不重排工具栏、不重做设备栏信息架构（第二步）
- 不换图标体系（NavBar 文字/符号图标本波不动）
- 不加动画（QSS 能力有限，且非本波目标）
- 不改功能行为、不动任何业务代码

**反目标（即使做完也视为失败）**
- 换皮后工业现场可读性下降（低分辨率 1366×768 下文字/表格被裁切）
- 双主题语义分叉（深色/浅色对同一状态给出不同颜色含义）
- 为「好看」引入 QSS 做不了的阴影/模糊/渐变伪实现，导致渲染异常

**第一步可实现边界（QSS 能力子集，评审确认）**

本波只承诺 QSS 能表达的效果。以下设计语言目标因 QSS 能力不足或需改控件/模型，**显式降级到第二步**（实施时按此标注，巡检不判为漏做）：

| 降级项 | 原因 | 第二步做法 |
|---|---|---|
| 逐列等宽字体（IP/路径/字节/时间/权限列） | QSS 无逐列选择器 | 代码按列设置 delegate 字体 |
| 日志行高 1.7 与逐行着色（时间戳/成功/错误分色） | QSS 无 line-height，逐行着色需富文本 | 日志控件改 HTML/富文本或按级别 QSS 类 |
| 进度条「完成 = success」伪态 | QProgressBar 无完成伪态 | 代码在 value==100 时切换样式类 |
| 连接状态点 8px / 统一机制 | FtpDeployWidget 内联 setStyleSheet 10px 圆点、WebSocket 页用「●」字形，两页机制不同 | 统一状态点控件 + QSS 类 |
| 表格行高 24px | FileBrowserPanel.cpp 的 `setDefaultSectionSize(22)` 会盖掉 QSS padding | 代码改行高或用 QSS 代理 |
| 空态引导块（居中文字+图标） | 需新增控件/覆盖层，触碰「不改布局」非目标 | 面板空态控件化 |

## 3. 约束

- **Qt QSS 能力边界**：无 `box-shadow`、无 `backdrop-filter`、渐变仅 `qlineargradient`/`qradialgradient`；层次必须靠纯色明度阶梯 + 1px 线实现
- 现有 QSS 两份各约 20KB，控件规则覆盖全界面；重写需保持选择器覆盖完整，不能漏控件（漏了就回退到默认 Qt 样式，浅色下尤其显眼）
- 工业密度：基础字号 9pt 保留；表格行高从 22px 提至 24px，面板内边距 12px（兼顾 1366×768）
- CI 是 Qt 6.9.2、本地 6.11.1——QSS 语法保持两者通用
- 现有测试 `tst_qss_pixels`（像素断言）与 `tst_theme` 必须同步更新并通过

## 4. 方案对比（已与用户讨论并选定）

| 方向 | 气质 | 与现状关系 | 结论 |
|---|---|---|---|
| A · Console 控制台（深炭黑 + 琥珀） | 专业工程软件、高密度 | 最接近现有「琴色」基因 | 未选：现代化增量有限，且用户日常用亮色 |
| **B · Instrument 精密仪器（冷灰白 + 深青）** | 高端测试仪器、冷峻精密 | 重做亮色主题，深色同步改 | **选定**：直接解决「单一白」，亮色日常场景最贴合 |
| C · Command 指挥中心（深海军蓝 + 电光青） | 监控大屏、氛围强 | 放弃琴色语义 | 未选：深蓝系在明亮车间表现一般，且改动面最大 |

选定理由：用户日常使用亮色主题、核心痛点是「白得单一/不像成品」；B 用冷灰与纯白拉开层次、用深青做信号色，专业且不刺眼。

### 5.2 字体与字号

| 用途 | 字体 | 字号/字重 |
|---|---|---|
| 界面文字 | `"Microsoft YaHei", "Segoe UI", sans-serif` | 9pt / 400（基础） |
| 分组标题、面板标题 | 同上 | 9.5pt / 600 |
| 窗口标题 | 同上 | 10pt / 600 |
| 数据（状态栏路径、日志等整类控件） | `Consolas, "Cascadia Mono", monospace` | 8.5pt / 400 |
| 表格行高 | — | 22px（**本波不改**，QSS 被代码 `setDefaultSectionSize(22)` 覆盖；24px 降级到第二步） |
| 日志行高 | — | 保持现状（QSS 无 line-height；1.7 降级到第二步） |

### 5.3 层次与分隔（不用阴影）

- 三级明度：canvas → panel → elevated（同级控件再用 `input` 凹槽）
- 分隔：普通分割用 `border` 1px；控件外框用 `borderStrong`；**焦点/选中用 2px accent**
- **活跃区标记**：Tab 激活、面板活跃区用 **2px accent 顶条**（`border-top: 2px solid accent`）——这是 Instrument 语言的记忆点，全界面只用在这一个语义上
- 表格选中行：`accentSoft` 底 + 左侧 2px accent 竖条
- 分组框 QGroupBox：panel 底 + border 边；标题左侧 2px accent 竖条（活跃/可选组）

### 5.4 控件形态规范

| 控件 | 规范 |
|---|---|
| 主按钮（`#btnPrimary`） | accent 填充 + `accentInk` 文字（浅色白字 / 深色深墨字）+ 4px 圆角 + 28px 高；hover accentHover、pressed accentPressed |
| 次按钮 | elevated 底 + borderStrong 边 + text 文字；hover 边框提亮至 textDim 色阶 |
| 输入框/QComboBox/QSpinBox | input 底 + border 边 + 4px 圆角；**:focus 时 2px accent 边** |
| 表格 | 表头 elevated 底 + textMuted 9pt；数据行 panel 底 + border 细分隔（55% 透明）；行高沿用 22px（24px 降级第二步） |
| 设备胶囊（chip） | panel 底 + borderStrong 边 + 999px 圆角；选中：accent 边 + accentSoft 底 + accent 文字 |
| 连接状态点 | **本波只换色值**（不改 10px 尺寸/机制）：灰 textDim（未连接）/ success（已连接）/ danger（失败）/ 灰闪（连接中）；8px 化降级第二步 |
| 进度条 | track = input 底；进行中 fill = accent（**「完成=success」伪态降级第二步**，本波单色） |
| 日志 | panel 底；**本波保持单色文本**（逐行着色/行高降级第二步）；级别色只用于既有富文本处 |
| 空态提示 | **本波沿用现有占位符/面包屑文案**（引导块降级第二步） |
| 状态栏 | panel 底 + border 顶线；文字 textDim；版本号 accent |
| 对话框 | panel 底；标题栏 elevated；按钮同主/次按钮 |
| 滚动条 | 轨道透明、滑块 border 色 + 圆角；hover 提亮 |

### 5.5 「青色是动词」语义（替换「琴色是动词」）

- **accent（深青/亮青）只用于「此刻可动作/此刻活跃」**：主按钮填充、`:focus` 边框、`:selected`/`:checked`、活跃 Tab/顶条、选中胶囊/行、分组标题竖条、进度条进行中
- **禁止**：静止结构边框、大面积填充、装饰性点缀
- 成功/失败用语义色（success/danger），不与 accent 混用
- 深色主题同样遵守，仅明度反转

### 5.6 现有「琴色是动词」处置

- 深色主题的琴色 `#F0A030` 全面由 `#2DD4BF`（亮青）替换：主按钮/焦点/选中/活跃 tab/状态点等
- QSS 注释与 CLAUDE.md 的主题设计原则章节同步改为「青色是动词」
- 涉及工具页的代码内嵌颜色（如状态点底色代码设置）需排查并替换（grep 颜色值 `#F0A030`、`#D48820` 等）

## 6. 双主题策略

- **主推浅色**（用户日常）：首屏默认主题仍为 dark（ConfigStore `appearance.theme` 默认值不变——**本波不改默认值**，只改视觉；是否改默认值由用户决定，见 §10 待定项）
- 深色同步重做，语义一致、明度反转
- 双主题均通过像素测试断言

## 11. 留给实施者的

- QSS 组织方式：直接手写两份（推荐，可读性好）或写生成脚本（token 表 → 两份 QSS）；若用脚本，放 `tools/devtools/` 并带测试
