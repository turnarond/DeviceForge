# FTP 部署双栏重构设计

**日期**：2026-07-25
**状态**：已完成（v2.4）
**关联**：[[2026-07-05-FTP部署改进设计]] | [[2026-07-04-工具框架设计]]

---

## 背景

DeviceForge 的 FTP 部署模块是面向新用户第一印象的核心功能。当前实现为纵向三段式布局（配置→操作→文件列表+进度+日志），交互模式为「选本地文件 → 点按钮部署」。与 Total Commander、FileZilla 等工具的双栏文件管理器体验相比有明显差距，用户在实际工作中会退回到 TC 做 FTP 文件传输。

差距的核心不是功能缺失，而是**交互模型**落后：用户无法同时看到本地和远程文件、无法拖拽上传、上传完成后不能即时目视确认结果。

同时，DeviceForge 拥有一项 TC/FileZilla 不具备的差异化能力：**多设备批量并行部署**。双栏重构要做的不是简单模仿 TC，而是「TC 的直观交互 + DeviceForge 的多设备批量能力」的组合。

## 目标

将 FTP 部署 Tab 从「表单式单栏布局」重构为「QSplitter 双栏文件管理器」，以双栏浏览 + 拖拽上传 + 远程文件管理 + 多设备批量部署作为推广阶段的旗舰功能。

## 一、整体布局

```
┌─ FTP 部署 ─────────────────────────────────────────────────┐
│ 工具栏: [目标设备 ▾ (3台)] [远程根路径: /apps/___ ] [FTPS ✓] [刷新] [端口: 21] │
│         [部署前清空远程目录 □] [部署完成后重启设备 □]      │
├────────────────────────┬───────────────────────────────────┤
│   📁 本地文件           │   📁 远程文件 (192.168.1.100)      │
│  ┌──────────────────┐  │  ┌───────────────────────────────┐ │
│  │ 路径: D:\firmware\│  │  │ 路径: /apps/m580cn/bin/       │ │
│  │                  │  │  │                               │ │
│  │ 📁 config/       │  │  │ 📁 config/                    │ │
│  │ 📄 app.bin  1.2M │  │  │ 📄 app.bin  1.2M  2026-07-20 │ │
│  │ 📄 params.ini 4K │  │  │ 📄 params.ini 4K  2026-06-15 │ │
│  │ 📄 boot.bin  256K│  │  │ 📄 boot.bin  256K  2026-03-01 │ │
│  │                  │  │  │                               │ │
│  └──────────────────┘  │  └───────────────────────────────┘ │
├────────────────────────┴───────────────────────────────────┤
│ 部署栏: [▶ 部署到 N 台设备]  [多设备进度]  [取消]          │
├────────────────────────────────────────────────────────────┤
│ 日志: [12:30:15] app.bin → 192.168.1.100 ✓ (1.2M, 3.2s)   │

```

- **左侧本地**：`QTreeView` + `QFileSystemModel`（Qt 内置）
- **右侧远程**：`QTableView` + 自定义 `RemoteFileModel`
- **中间分隔条**：`QSplitter`，可拖拽调整左右比例
- **底部日志**：按设备分组显示部署结果
- **顶部工具栏**：设备多选下拉 + 远程路径 + 选项 checkbox

## 二、多设备批量部署

### 设备选择

设备下拉框支持多选（可勾选的列表），设备来自 `DeviceBusWidget`。右侧远程面板默认显示第一台设备的目录内容，用户可通过下拉切换查看不同设备的远程文件。

### 部署逻辑

1. 用户通过拖拽/添加将本地文件加入左侧列表
2. 点击「部署到 N 台设备」
3. Backend 并行上传到所有已选设备（`QFutureWatcher`，默认最大并行 4）
4. 全局进度条显示总文件数进度
5. 每台设备的结果独立记录日志
6. 部署完成后右侧远程面板自动刷新当前设备

### 日志格式（按设备分组）

```
[12:30:15] === 192.168.1.100 ===
[12:30:15] ✓ app.bin    (1.2M, 3.2s)
[12:30:18] ✓ params.ini (4K,   0.1s)
[12:30:18] === 192.168.1.101 ===
[12:30:18] ✓ app.bin    (1.2M, 3.5s)
[12:30:22] ✓ params.ini (4K,   0.1s)
[12:30:22] === 192.168.1.102 ===
[12:30:22] ✓ app.bin    (1.2M, 3.1s)
[12:30:25] ✗ params.ini (连接超时)
```

### 部署选项

工具栏保留两个 checkbox（对所有目标设备统一生效）：
- **部署前清空远程目录**：先 `clearRemoteDirectory()` 再上传
- **部署完成后重启设备**：上传完毕后发出重启指令

## 三、远程文件面板

### 表格结构

| 列 | 内容 |
|----|------|
| 图标 | 📁（目录）/ 📄（文件） |
| 名称 | 文件/目录名，目录可点击进入 |
| 大小 | 人类可读格式（KB/MB/GB） |
| 修改时间 | `yyyy-MM-dd hh:mm` |
| 权限 | Unix 权限字符串（如 `rw-r--r--`），Windows FTP 则为 `—` |

### 交互

| 操作 | 方式 |
|------|------|
| 进入目录 | 双击目录行 |
| 返回上级 | 面包屑导航任意层级跳转 |
| 刷新 | 刷新按钮 / F5 快捷键 |
| 下载 | 右键菜单 → 保存到本地 |
| 删除 | 右键菜单 → 确认弹窗后删除（支持多选批量） |
| 重命名 | 右键菜单 → 原地编辑，回车确认 |
| 新建目录 | 右键菜单 → 输入名称创建 |
| 复制路径 | 右键菜单 → 复制 FTP 完整路径 |

### 面包屑导航

```
/apps / m580cn / bin /
```

点击任意层级直接跳转，当前目录高亮。

### 对比提示（行背景色）

| 颜色 | 含义 | 触发条件 |
|------|------|----------|
| 🟢 绿 | 已同步 | 远程文件与本地同名文件大小和时间一致 |
| 🟡 黄 | 有差异 | 远程有同名文件但大小或时间不同 |
| ⚪ 无 | 远程独有 | 本地没有对应文件 |

对比在用户拖拽/添加文件到本地列表时触发（仅基于文件名和大小比对，不需要连接设备）。

## 四、本地文件面板

- `QTreeView` + `QFileSystemModel`，无额外开发
- 路径栏支持手动输入 + 回车跳转
- 「打开目录」按钮用 `QFileDialog::getExistingDirectory`

## 五、拖拽交互

| 拖拽操作 | 行为 |
|----------|------|
| 本地面板 → 远程面板 | 上传选中文件到当前远程目录 |
| 系统资源管理器 → 本地面板 | 切换本地目录到拖入的文件夹 |
| 系统资源管理器 → 远程面板 | 直接上传拖入的文件到远程当前目录 |

日志即时反馈拖拽结果：
```
[12:30:15] 📤 拖拽上传: app.bin → 192.168.1.100:/apps/m580cn/bin/ ✓
```

## 六、FTP LIST 解析器

FTP 没有标准的目录列表格式。`LIST` 命令返回服务器原生格式，需要解析器支持两种常见格式：

**Unix（ls -l）**：
```
-rw-r--r-- 1 user group 1234567 Jul 20 14:30 app.bin
drwxr-xr-x 2 user group    4096 Jul 19 09:12 config
```

**Windows（dir）**：
```
07/20/2026  02:30 PM         1,234,567 app.bin
07/19/2026  09:12 AM    <DIR>               config
```

`FtpListParser` 负责将原始文本解析为结构化的 `FtpFileInfo` 列表。
