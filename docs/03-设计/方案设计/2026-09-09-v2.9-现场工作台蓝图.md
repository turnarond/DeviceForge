# DeviceForge v2.9 现场工作台蓝图

**日期**：2026-09-09 ｜ **状态**：方案评审通过
**需求**：`docs/02-需求分析/2026-09-09-v2.9-现场工作台与可靠传输.md`

## 1. 版本主题

v2.9 的主题为 **现场工作台与可靠传输**。版本成功不以新增协议数量衡量，而以工程师能否长期驻留在 DeviceForge 中，连续完成设备选择、文件浏览、上传下载、批量部署、失败恢复和调试切换衡量。

## 2. 子设计与依赖

| 顺序 | 子设计 | 交付目标 |
|---|---|---|
| 1 | `2026-09-09-v2.9-传输可靠性内核设计.md` | 三条传输链路共享可靠性语义 |
| 2 | `2026-09-09-v2.9-现场工作区体验设计.md` | 文件与设备成为稳定工作上下文 |
| 3 | `2026-09-09-v2.9-快速启动与懒加载设计.md` | 首窗优先、非首屏按需加载 |

可靠性内核是工作区任务体验的前置。快速启动可独立推进，但最终生命周期必须与工作区模型一致。

## 3. 总体架构

```text
主窗口外壳
├── 固定设备上下文
├── 工作区容器
│   ├── 文件工作区（默认，双栏 + 任务抽屉）
│   └── 命令/通信/测试/诊断/OPC UA（首次访问加载）
└── 全局日志

文件工作区 / 批量部署
        ↓
统一 TransferTask / TransferScheduler / TransferExecutor
        ↓
内部 ITransferChannel 包装层
        ↓
既有 FtpAdapter / SshAdapter
```

## 4. 约束

- 保持 `IProtocolAdapter`、`IDeployable` 兼容，不在本版启用插件化或 ToolHost 多活跃能力。
- UI 不直接执行网络操作；异步回调必须使用代际令牌和安全对象守卫。
- 配置继续使用 ConfigStore；敏感数据继续使用 DPAPI；日志继续脱敏。
- CI 兼容 Qt 6.9.2，不采用 Qt 6.11.1 独有 API。
- 不把批量部署的清目录、设备结果和报告语义下沉到通用文件传输层。

## 5. 交付顺序

`蓝图与路线图对账 → 传输可靠性内核 → 现场工作区体验 → 快速启动 → 全链路长稳验收`

每个子设计独立形成实施计划、TDD 红绿重构记录和评审出口；不得用后续子设计阻塞前一子设计的可验证交付。
