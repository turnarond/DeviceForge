# DeviceForge v2.9 传输可靠性内核设计

**日期**：2026-09-09 ｜ **状态**：方案评审通过
**上位蓝图**：`2026-09-09-v2.9-现场工作台蓝图.md`

## 1. 目标与非目标

统一双栏上传、双栏下载和批量部署的任务状态、错误分类、重试、取消、原子交付与结果模型。保留双栏与批量部署各自的业务编排。

本期不做字节级断点续传、跨重启恢复、全局任务中心、SCP 或协议 ABI 重构。

## 2. 组件边界

新增 `src/transfer/` 领域层：

| 组件 | 职责 |
|---|---|
| `TransferTask` | 一次用户操作的不可变请求：方向、源、目标、设备快照、协议、文件与策略；不长期保存明文密码 |
| `TransferItem` | 单文件状态：字节数、尝试次数、临时路径、基线元数据和结果 |
| `TransferPolicy` | 重试、退避、覆盖、原子提交和并发约束 |
| `TransferError` | 稳定错误码、用户提示、原始摘要、是否可重试 |
| `TransferExecutor` | 单文件连接、传输、校验、提交、清理与重试 |
| `TransferScheduler` | 按设备键排队、跨设备并发、取消与事件发布 |
| `TransferResult` | 供任务抽屉、部署报告和失败重试消费的统一结果 |
| `ITransferChannel` | 内部协议包装：上传、下载、重连、改名、删除、元数据和能力查询 |

`ITransferChannel` 包装现有 FtpAdapter/SshAdapter，不改变 `IProtocolAdapter` 和 `IDeployable`。`DeployJob` 首先委托 `TransferExecutor`，再逐步迁移通用聚合逻辑；部署事务语义仍留在 FtpDeployTool。

## 3. 状态机

```text
Queued → Preparing → Transferring → Verifying → Committing → Succeeded
                     │                    │
                     ├→ Reconnecting ─────┘
                     ├→ NeedsAttention
                     ├→ Failed
                     └→ Cancelled
```

- 瞬时网络故障进入 Reconnecting，短退避后最多重试 2 次。
- 认证、权限、非法路径、本地文件消失和确定性 I/O 错误直接 Failed。
- 覆盖决策在提交任务前完成；执行中若目标相对基线发生变化，进入 NeedsAttention，不静默覆盖。
- 用户取消后在 1 秒内或最近协议检查点进入 Cancelled；终态不可回退。

## 4. 原子交付与恢复

- 上传写远端临时名，校验字节数后改名提交；失败或取消尽力清理临时文件。
- 下载写本地临时文件，校验后替换目标。
- 协议或设备不支持可靠改名时允许直接写入，但结果必须带 `nonAtomic=true` 和可见告警。
- 目录任务按文件恢复，重试时跳过已成功项；不承诺单文件字节偏移恢复。
- 批量部署由 `DeployJob` 保留连接、清目录、目录规划及报告事务，每文件建立任务私有凭据并委托 `TransferExecutor`。目录映射保持原行为：FTP 包含本地顶层目录，SFTP 上传目录内容；空目录和嵌套目录通过适配器显式创建/确认。
- 失败设备按钮通过 `resumePreviousFailures()` 显式标记下一次 `startUpload`，不改变既有上传及完成回调签名。后端按请求身份（协议/FTPS、用户、端口、源清单、目标目录）与设备匹配上轮交付记录，恢复不重复清目录；普通部署不跳过文件。记录只保存源/目标路径和交付方式，不保存凭据，不支持跨重启恢复。
- 部署 CSV/HTML 保留原六列顺序，追加 `non_atomic`；单文件非原子结果向设备报告聚合，同时输出可见日志。提交前取消记 `Cancelled`，提交后取消保留已交付事实；存在余项时设备为 `Cancelled` 并保留交付清单。
- F6 移动仅在目标原子提交成功后删除源；删除失败则结果为“复制成功、源清理失败”，不得谎报移动成功。

## 5. 调度与冲突

- 设备键为“协议 + 主机 + 端口 + 用户身份”；同键严格 FIFO。
- 不同设备按现有 1–8 并发配置执行。
- 本地提交按规范化目标路径互斥，避免多个下载同时替换同一文件。
- 相同远端目标路径存在排队或运行任务时拒绝新任务并提示冲突。
- 队列任务可取消；本期不提供暂停、恢复按钮或拖动排序。

## 6. 事件与生命周期

事件限定为 `TaskAdded`、`TaskStateChanged`、`ItemProgress`、`ItemFinished`、`TaskFinished`。进度按 100 ms 节流；状态切换和终态立即发布。事件携带任务 ID、代际编号和不可变快照，UI 只订阅事件，不持有工作线程对象。

关闭应用时先停止接收新任务，再取消并等待在途任务收口，清除任务私有 AuthInfo，最后销毁协议对象。切换设备只影响新任务，运行任务始终绑定创建时的设备快照。

## 7. 错误处理与覆盖策略

- 双栏任务开始前一次选择“覆盖全部、跳过全部、取消”，批次内不重复弹窗。
- 批量部署默认原子覆盖；失败重试沿用原任务策略。
- 后台执行不弹阻塞式对话框；需要决策时进入 NeedsAttention，由任务抽屉承载。
- 协议原始错误仅作为脱敏摘要保存，不将密码或报文内容写入日志与报告。

## 8. 测试与验收

- 纯逻辑：状态迁移、错误分类、退避、覆盖、路径和临时命名。
- Mock Channel：重连、两次重试、取消、原子提交、清理失败和非原子降级。
- Scheduler：同设备无并发、跨设备并行、FIFO、路径冲突和终态必达。
- 集成回归：既有 `tst_deploy_runner` 保持全绿；新增双栏上传、下载、移动、代际和 UAF 测试。
- 故障注入：断网、服务重启、权限拒绝、磁盘满、文件消失和应用关闭。
- 100 轮启停/取消/切换后线程、socket、文件句柄回到基线。
