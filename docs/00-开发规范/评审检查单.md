# 评审检查单

> 用于 SDD 关键阶段的专家评审（规范第 14、16 条）。按阶段使用，**全部为强制项**；任何一项不通过即评审不通过。
> 长稳（内存/句柄/连接泄漏）检查在三个评审中都要执行。

---

## 一、方案设计评审（强制门禁，不通过不得开发）

### 需求与范围
- [ ] 每条需求都有对应设计，无遗漏
- [ ] 范围 In/Out 清晰，无越界设计

### 架构（规范第 8 条）
- [ ] 分层保持（UI → 业务 → 适配器/基础设施），无反向依赖
- [ ] 复用既有机制（lwserverbase / lwmsgq / IProtocolAdapter / ConfigStore / QSS 双主题），未绕开
- [ ] 全局影响面已评估（生命周期、并发、配置、UI 布局），无"局部舒服全局别扭"

### 接口与兼容性（规范第 13 条）
- [ ] 新接口与既有接口风格一致
- [ ] 对外 SDK：头文件/接口改动**向前兼容**，无 ABI 破坏；不兼容变更已升 MAJOR + 迁移说明

### 并发与生命周期
- [ ] 线程模型明确（主线程/后台线程/QtConcurrent/回调线程）
- [ ] 锁、代际令牌、QPointer 守卫等竞态防护设计到位
- [ ] 停止/析构路径：无 UAF、无悬挂回调、无僵尸定时器

### 长稳（规范第 14 条）
- [ ] 内存：所有分配有释放路径；无循环引用、无泄漏
- [ ] 句柄：socket / 文件 / 窗口句柄有明确关闭路径；连接池有上限与超时清理
- [ ] 长稳测试用例已列入计划（重复连接断开、长时间运行、资源曲线监控）

### 安全
- [ ] 凭据：不落明文（DPAPI / 内存擦除）、日志去敏感化
- [ ] 输入校验：路径穿越、非法地址 fail-closed、注入防护
- [ ] 网络暴露面：绑定地址、鉴权、警告提示

### 测试策略（规范第 6 条）
- [ ] TDD 用例清单（红-绿目标）明确
- [ ] 边界用例（空输入、超时、断网、取消）覆盖
- [ ] 错误路径用例（失败不静默、错误上报）覆盖

### 文档（规范第 2 条）
- [ ] 需同步更新的文档清单（白皮书 / 用户手册 / 接口参考 / 架构 / 规范）已列出
- [ ] 版本号变更清单（如涉及）已列出

### 风险与回滚
- [ ] 失败影响面分析、回滚方式明确

## 二、代码评审（PR）

- [ ] TDD：有对应测试且**全部绿**（红灯代码不合并）
- [ ] 整洁（规范第 7 条）：无死代码、无调试残留、无注释掉的代码、无魔法数字
- [ ] 架构（规范第 8 条）：分层正确、未绕开既有机制
- [ ] 资源：每个 `new`/句柄/socket 都有释放路径；RAII 使用正确
- [ ] 错误处理：失败上报而非静默；workaround 带 issue 链接
- [ ] 文档：**同一提交内**文档已同步（规范第 2 条）
- [ ] 分支：单主题分支（规范第 4 条），无无关改动混入

## 三、交付评审（发布）

- [ ] `versioncheck.py` 全仓版本一致（规范第 2、10 条）
- [ ] `ctest -C Release --output-on-failure` 全量绿
- [ ] `smoke.py` 冒烟通过（启动 → 主窗口出现 → 正常退出）
- [ ] 验收标准逐项确认（版本边界，规范第 10 条）
- [ ] `CHANGELOG.md` / `RELEASE_NOTES.md` 已更新
- [ ] tag `vX.Y.Z` 已打（annotated，含版本号/日期/变更摘要）
- [ ] 发布包完整（exe + DLL + Updater.exe + 资源）

---

## 长稳专项检查（分析/评审/测试通用）

- [ ] 内存曲线：长时间运行（≥ 8h 或 ≥ 10 万次操作）内存不持续增长
- [ ] 句柄曲线：GDI/User/文件/套接字句柄数不随操作累积
- [ ] 连接生命周期：重复 连接→操作→断开 循环后资源归零
- [ ] 线程：无泄漏线程、无死锁、无忙等
- [ ] 定时器/回调：stop 后无遗留定时器与回调触发
- [ ] 长稳发现问题：记入 issue（规范第 9 条），不静默修复
