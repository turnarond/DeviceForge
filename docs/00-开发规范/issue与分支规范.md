# issue 与分支规范

> 对应开发规范第 4、9、11、12 条。

---

## 1. issue 分类与模板

### 分类
- `bug`：缺陷（含长稳问题：内存/句柄泄漏）
- `feature`：新需求
- `enhancement`：既有功能增强
- `docs`：文档问题（文档腐败、失效引用）
- `vendor`：**供应商问题**（上游工程 / SDK / 文档供应商的责任，见第 3 节）

### 通用模板
```markdown
**标题**：<一句话概括，如> fix: 远程面板重连后列表不刷新
- 环境：版本 vX.Y.Z / OS / 硬件
- 现象：
- 期望：
- 复现步骤：
  1.
  2.
- 日志 / 截图 / dump：
- 影响范围与优先级：P0/P1/P2
```

### 长稳类 issue 补充项
- 运行时长、操作频率、内存/句柄曲线、是否可复现

## 2. 分支命名与生命周期

- 命名：`feature/xxx`、`fix/xxx`、`docs/xxx`、`refactor/xxx`、`chore/xxx`；可附 issue 号（`fix/xxx#12`）。
- 一律**从 `main` 新建**；合回 `main` 用 `--no-ff`（保留 merge commit）；合并后删除分支。
- **一个分支一个主题**，不混入无关改动（评审检查单强制项）。
- 急修（hotfix）可短暂例外，但必须说明并事后补 issue。
- 大改动（重构/多文件）必须走方案设计评审（SDD 阶段 1）再开分支。

## 3. 供应商问题（vendor）

- **排查可以，解决不要混入本工程**（规范第 11 条）：把问题提给对应工程 / SDK / 文档供应商。
- 本工程内建 `vendor` issue 记录：`[vendor] <上游名>: <问题>`，正文写清归属、复现、期望上游处理，并链接上游 issue。
- 本工程提交中不得包含"顺手修的上游问题"，除非上游明确授权。

## 4. 问题记录（当前没时间改）

- 开发中发现、当下无时间修复的问题 → **立即提 issue**（一句话也行：现象 + 位置 + 影响），避免遗忘（规范第 9 条）。
- 临时规避代码注释必须带 `workaround: issue #NNN`。

## 5. 重构门禁（规范第 12 条）

- **触发条件**：与整体架构冲突大 / 影响面大 / 改动别扭。
- **流程**：讨论（动机、影响面、兼容性、回滚）→ 重构方案文档 → 评审 → `refactor/xxx` 分支 → 实施 + 全量回归。
- 禁止"顺手重构"：重构与功能开发分离。
