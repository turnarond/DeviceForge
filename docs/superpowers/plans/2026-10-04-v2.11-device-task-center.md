# v2.11 设备档案与现场任务中心实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 v2.10 可靠传输与批量命令能力之上，增加跨协议设备档案、可复用任务模板、可恢复执行引擎和执行历史。

**Architecture:** 以 `DeviceRegistry` 统一物理设备与协议端点，以 `TaskTemplateStore` 保存不含密码的任务定义；`TaskExecutionEngine` 编排现有 `TransferScheduler` 与 `BatchCommandRunner`，并将设备级/步骤级结果写入 `TaskRunStore`。`TaskCenterWidget` 只依赖业务接口，不直接访问协议库。

**Tech Stack:** Qt 6.9+ API 子集、C++17、QtTest/CTest、ConfigStore(SQLite + DPAPI)、现有协议适配器、TransferScheduler、BatchCommandRunner。

**Spec:** `docs/superpowers/specs/2026-10-04-v2.11-device-task-center-design.md`

## Global Constraints

- 全部新增 UI、日志和文档使用中文；协议名、API 和枚举可保留英文。
- 不绕过 `IProtocolAdapter`、`IDeployable`、`TransferScheduler` 或 `BatchCommandRunner` 直接连接协议库。
- 密码只由 ConfigStore/DPAPI 管理；模板、日志、报告和错误文本不得保存密码明文。
- 稳定设备身份由 `deviceId` 表示；同一物理设备的 FTP/SFTP/SSH/Telnet/Modbus 端点共享名称。
- 现有 `DeviceInfo::alias` 映射为设备名称；旧配置必须可回退读取。
- 保持现有单次 FTP/SFTP 部署、双栏文件操作和批量命令入口兼容。
- 兼容 CI Qt 6.9.2，不使用仅 Qt 6.11 可用的 API。
- 每个任务必须先写失败测试，再实现，再运行目标测试并单独提交。

## Review Focus

- 同一 IP 的不同协议端点是否错误地产生多个物理设备：由 Task 1 的端点归并测试锁定。
- 旧 `DeviceInfo`/旧 ConfigStore 数据缺少 `deviceId` 或名称：由 Task 2 的迁移与回退测试锁定。
- 模板中误写密码或命令敏感输出：由 Task 3 的敏感字段排除测试锁定。
- 重试时重复执行已成功的文件/命令步骤：由 Task 4 的阶段恢复测试锁定。
- 重启断开、取消和部分成功同时发生：由 Task 4/5 的状态机与记录一致性测试锁定。
