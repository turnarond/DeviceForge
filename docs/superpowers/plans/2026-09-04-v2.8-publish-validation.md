# v2.8 Publish Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete and evidence the v2.8 portable release validation loop without changing runtime product behavior.

**Architecture:** Keep GitHub Actions as the single ordered validator: version gate, build, CTest, Qt deployment, portable ZIP, hermetic extracted-package Smoke, and artifact upload. Local commands and the acceptance report use the same entry points and explicitly separate automatic passes from manual, environmental, and safety blockers.

**Tech Stack:** GitHub Actions on Windows, PowerShell, CMake/Visual Studio 2022, Qt 6.9.2, Python 3.12 in CI, Python unittest, `windeployqt`, portable ZIP.

**Spec:** `docs/03-设计/方案设计/2026-09-04-v2.8-发布验证专项设计.md`

## Global Constraints

- Do not modify `src/`, public ABI, or runtime product behavior.
- The release artifact is portable ZIP only; do not build, upload, or distribute NSIS until its recursive uninstall behavior is fixed by an independent PATCH.
- Missing, unparsable, or mismatched values in any of the 9 mandatory version sources fail the gate.
- Every failed check must preserve its command, environment, time, exit code, and log or artifact path.
- Do not claim remote CI, portable Smoke, real FTP/SFTP, or long-stability completion without the corresponding run evidence.
