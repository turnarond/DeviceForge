# v2.10 批量命令与部署后重启实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 抽取统一的 Telnet/SSH 批量命令执行内核，并让文件部署后的重启选项真正对部署成功设备发送命令。

**Architecture:** 新增 `BatchCommandRunner` 作为 UI、批量命令 Tool 和 FTP 部署 Backend 共享的服务层。Runner 通过 `ProtocolRegistry` 创建 Telnet/SSH 适配器，逐设备执行命令并报告连接、执行、重试、取消和“重启已触发”状态；UI 只负责收集配置和展示结果。

**Tech Stack:** Qt 6.9/6.11、C++17、QtTest/CTest、`IProtocolAdapter`、`ProtocolRegistry`、`ConfigStore`、QtConcurrent。

**Spec:** `docs/03-设计/方案设计/2026-09-28-v2.10-批量命令与部署后重启设计.md`

## Global Constraints

- 全部用户可见文案和文档使用中文；协议名、API 名和 ABI 专有名词保留英文。
- 依赖方向保持 UI → 业务 → 适配器；部署 Backend 不依赖 TelnetWidget 或 TelnetBackend。
- 命令执行必须通过 `IProtocolAdapter`/`ProtocolRegistry`，不得绕过适配器直接调用 libcurl/libssh2。
- 用户名和密码只存在于任务生命周期，结束时调用 `AuthInfo::clear()`，日志不得输出凭据或未经脱敏的命令原文响应。
- Telnet 默认端口 23，SSH 默认端口 22；命令默认超时 10 秒，默认失败重试 1 次。
- 取消必须停止派发新设备，并在适配器安全检查点结束当前任务；不得留下写 UI 的悬空回调。
- 现有批量命令 UI 和部署可靠传输行为不得回退；新增测试必须注册到 `tests/CMakeLists.txt` 和 CTest。

## Review Focus

- 重启命令发送后设备主动断开：应标记为“重启已触发”，不能误报为发送失败；由 Task 1 的 `rebootDisconnectAfterSend` 测试覆盖。
- 部署批次中混合成功、失败和取消设备：只有成功设备收到重启命令；由 Task 3 的 `rebootOnlySuccessfulDevices` 测试覆盖。
- SSH 与 Telnet 默认端口和协议键不一致：必须分别产生 22/23；由 Task 1 的 `protocolDefaultPort` 测试覆盖。
- 认证失败与瞬时网络错误：前者不重试，后者按策略重试；由 Task 1 的 `retryClassification` 测试覆盖。
- 用户在任务运行期间销毁工具或点击取消：后台任务不得回调已销毁 UI；由 Task 2 的 `cancelStopsCallbacks` 测试覆盖。

### Task 1: 新增批量命令类型与共享执行内核

**Files:**
- Create: `src/command/CommandTypes.h`
- Create: `src/command/BatchCommandRunner.h`
- Create: `src/command/BatchCommandRunner.cpp`
- Modify: `CMakeLists.txt`
- Create: `tests/command/tst_batch_command_runner.cpp`
- Modify: `tests/CMakeLists.txt`

**Interfaces:**
- `CommandTypes.h` produces `CommandRequest`, `CommandDeviceResult`, `CommandBatchResult`, `CommandResultState` and `RebootOptions`.
- `BatchCommandRunner::run(const CommandRequest&, std::atomic_bool&, Callbacks)` executes one batch synchronously on its caller thread; callers place it in QtConcurrent when asynchronous behavior is needed.
- `Callbacks` provides `onDeviceResult`, `onLog`, and `onFinished`; callbacks never receive plaintext credentials.
- Runner consumes `ProtocolRegistry::create()`, `IProtocolAdapter::connect/request/disconnect`, and `TransferTypes::classifyTransferError`-style retry classification moved into command-local helpers.
