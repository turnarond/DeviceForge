# v2.13 任务模板导入/导出设计（跨机迁移）

**日期**：2026-10-16 ｜ **分支**：docs/v2.13-template-transfer-spec ｜ **状态**：待用户审阅
**定位**：v2.13 轻还债版的宣传向新特性——"一台机器调好的批量部署模板，U 盘带到另一条产线直接导入"。

## 1. 背景与目标

v2.11 设备任务中心的模板（`TaskTemplate`）只能在本机 ConfigStore 中使用；换一台机器就要重敲一遍模板与步骤参数。本特性提供**单模板**的导出/导入文件通道：

- 导出：选中模板 → 存为 JSON 文件。
- 导入：选文件 → 校验 → 落库为新模板（可选覆盖/改名解决同名冲突）。
- 成功标准：跨机导入的模板可立即进入既有的"圈选设备→执行"流程；文件格式是公开契约（带魔数与版本闸），旧版本程序遇到未知高版本必须明确拒绝而不是误解。

**明确不做（YAGNI）**：全模板集打包导出（与 ConfigStore 既有全库 JSON 导入导出重叠）；设备档案随模板导出（跨机 DPAPI 凭据不可携带，交互成本不匹配本版本体量）；导入后自动建档案；拖拽导入。

## 2. 文件格式契约

单文件 = 单模板，UTF-8 JSON：

```json
{
  "format": "deviceforge.task-template",
  "formatVersion": 1,
  "template": {
    "name": "…", "description": "…", "version": 1,
    "deviceIds": ["device-…"], "tagSelectors": ["A线"],
    "steps": [ { "type": "deploy_files", "parameters": {…} }, … ],
    "unknownFields": {…}
  }
}
```

- `template` 对象的字段编码与 `TaskTemplateStore` 现行行编码**同源**（见 §3 外提重构），不另起字段口径。
- **不含 templateId**（导出时丢弃）：导入一律作为新模板落库、由 store 生成新稳定 ID；跨机场景 ID 语义（本机主键）不外溢。
- **不含任何凭据秘密值**：模板模型本来只存 `credentialRef` 引用（v2.11 纪律）；导入解码沿用 store 既有的 `containsSensitiveKey` 拒收守卫，手工构造的恶意文件同样被拒。
- `formatVersion` 治理：本程序只认 `1`；**高于当前支持的版本 → 拒绝**，提示"请用更新版本的 DeviceForge 导入"。字段级前向兼容由 `unknownFields` 原样保留承接（既有机制），未来 bump 版本的翻译规则届时另立规格。
- 文件扩展名 `.json`；无专用扩展名诉求（用户多途径中转）。

## 3. 组件与数据流

| 单元 | 职责 | 位置 |
|---|---|---|
| `TaskTemplateCodec`（新增） | 纯逻辑：`encodeTemplateFile(const TaskTemplate&) → QByteArray`（缩进美化）/ `decodeTemplateFile(const QByteArray&) → std::optional<TaskTemplate>`（失败给出人读原因） | `src/task/TaskTemplateCodec.{h,cpp}` |
| `TaskTemplateStore`（重构） | 把 `encodeTaskTemplate`/`decodeTaskTemplate`（现为 .cpp 匿名命名空间）外提到 `TaskTemplateCodec.h/.cpp`，store 与文件通道共用同一字段口径；行为不变 | src/task/ |
| `TaskCenterWidget`（扩展） | 模板栏工具条新增「导入模板」「导出模板」按钮；编排 QFileDialog、同名冲突弹窗、结果提示；落库走 store.save() | src/ui 既有文件 |

依赖方向 UI → 业务（codec/store），无新增第三方依赖。`TaskTemplateCodec.h` 仅依赖 Qt Core——纯头+cpp，可脱离窗口直测（tests/AGENTS.md 可测性约定）。

数据流：
- 导出 = 选中模板 → `encodeTemplateFile` → 写文件。
- 导入 = 读文件 → `decodeTemplateFile`（魔数/版本/结构/敏感键四道校验）→ 同名检查 → 三选一：**新建/改名**分支 `templateId.clear()` 后 save()（store 生成新稳定 ID）；**覆盖**分支把既有同名模板的 templateId 赋入后 save()（原位覆写）。→ 刷新列表 + 提示摘要。

## 4. 交互流程

**入口**：任务中心页模板列表工具条，两个按钮：
- 「导出模板」：未选中模板时禁用。点击 → QFileDialog::getSaveFileName，默认名 = 模板名经文件名非法字符清洗 + `.json`（空名回退 `task-template.json`）；写成功弹信息框（含路径），写失败弹错误框（路径+系统错误）。
- 「导入模板」：恒可用。点击 → QFileDialog::getOpenFileName（JSON 过滤器）→ 读文件失败/解码失败 → 错误框给出分类原因（§5）；成功 → 冲突与提示流程（下）。

**同名冲突**（`name` 与既有模板相同，大小写敏感精确匹配）：三选弹窗「覆盖同名 / 另存为"名称 (2)" / 取消」。
- 覆盖：以既有同名的 templateId 覆写保存（模板内容替换，历史执行记录不受影响——记录本来就是不可变快照）。
- 自动改名：`"名称 (2)"`，若仍冲突递增 `(3)`…（循环至空位，不设硬上限）。
- 取消：不落库。

**导入成功提示**（信息框两行）：
1. `已导入模板「X」（N 个步骤）`；
2. 若存在本机缺失的设备引用：`引用了 M 个本机不存在的设备档案，建好同端点档案后自动接上`——**悬空 deviceIds 原样保留不剥离**（已拍板）；`tagSelectors` 不做存在性校验（标签是松引用，执行期圈不到即空选，维持既有语义）。

## 5. 错误处理

解码拒绝分类（人读文案，进错误框）：
- 非法 JSON（解析失败，附字节偏移）；
- 魔数不符：`不是 DeviceForge 模板文件`；
- `formatVersion` 缺失/非 1/过高：过高 → `模板文件版本(vN)比本机程序更新，请升级 DeviceForge 后导入`；
- `template` 对象缺失或必填字段非法（复用 store decode 的既有分类文案：结构非法、含敏感凭据字段拒收等）。
- 文件读取失败（不存在/无权限）：路径 + 系统错误。

原则：导入校验全部通过才落库，**不落半成品**；覆盖路径同样先整体校验后一次 save()。

## 6. 测试（TDD 主场）

**新目标 `tst_task_template_codec`**（纯逻辑，注册进 tests/CMakeLists.txt，全量 45→46）：
1. 往返一致：完整模板（多步骤/多设备/标签/描述/unknownFields）encode→decode 字段逐一相等；
2. 悬空引用保留：deviceIds 指向不存在档案，decode 不丢；
3. unknownFields 原样保留；
4. 坏文件三类拒绝：非法 JSON / 魔数不符 / formatVersion=2（过高）；
5. 版本闸边界：formatVersion=1 通过，缺失拒绝；
6. 敏感字段拒收：手工塞入 `password` 键的文件被 decode 拒绝（继承 store 守卫）；
7. templateId 不外溢：编码结果不含 templateId 字段。
8. （重构守卫）store 行为回归：外提后 tst_task_template_store 既有用例不改而全绿。

**`tst_task_center_widget` 扩**（QTimer 布防模态弹窗既有模式）：
1. 导出写临时文件 → 内容含魔数；未选中时按钮禁用；
2. 导入新文件 → 列表 +1、悬空引用提示文案出现在弹窗；
3. 同名冲突三选（覆盖分支）→ 列表数量不变、内容被替换；
4. 坏文件导入 → 不落库、错误框出现。

## 8. 已拍板决策记录

| 决策点 | 结论 | 备选与否决理由 |
|---|---|---|
| 导出粒度 | 单模板 | 全量打包与 ConfigStore 全库导出重叠；模板+档案绑定涉跨机凭据难题 |
| 悬空 deviceIds | 保留+提示 | 剥离破坏"先带模板后建档"顺序；阻断则跨机基本不可用；deviceId=端点哈希使同端点档案自动接上 |
| templateId | 导出丢弃，导入恒生成新 ID | 保留会与他机主键语义冲突 |
| 同名策略 | 覆盖/自动改名/取消三选 | 静默改名不可控；直接拒绝不友好 |
| 字段编码 | 外提 store 私有 encode/decode 共用 | 双口径必然漂移 |
| 版本闸 | 只认 formatVersion=1，高版本拒绝 | 前向猜测解码=静默错数据风险 |
