# v2.13 任务模板编辑器设计（新建/编辑/删除入口，#54）

**日期**：2026-10-16 ｜ **分支**：docs/v2.13-template-editor-spec ｜ **状态**：待用户审阅
**票面**：#54——任务模板无产品内新建/步骤编辑入口（v2.11 规格"支持将当前配置保存为新模板"未落地，模板只能靠复制/导入产生，第一份模板无从而来）
**已拍板**：方案 B（任务中心编辑器）；删除模板入口并入本票（用户答复 A）。

## 1. 范围与入口

- 左栏「任务模板」组顶部迷你工具条：**[新建模板] [删除]** 两按钮（objectName：`taskNewTemplateButton` / `taskDeleteTemplateButton`）。
- 中栏摘要行加 **[编辑当前模板]**（`taskEditTemplateButton`，未选中禁用）。
- 双击左栏模板行 = 编辑（对齐胶囊双击编辑档案的既有习惯）。
- 编辑器为独立对话框 `TaskTemplateEditorDialog`（src/task/，先例 DeviceProfileEditorDialog）；中栏只读展示不动。

**不做（YAGNI，留档）**：部署侧"保存当前配置为模板"一键捕获（后续增强票）、模板多版本历史、步骤参数富语法（变量/引用）。

## 2. 引擎参数契约（编辑器必须产出的字段，逐字一致）

| 步骤类型 | 参数键 | 取值口径 |
|---|---|---|
| deploy_files | `items[]`：`localPath`/`remotePath`（必填非空）、`direction`=`upload`(缺省)·`download`、`overwrite`=`overwrite`(缺省)·`skip`；可选 `protocol` | 简写 `files[]`+`remoteDirectory` 仅兼容读取：打开时展开成 items[]（remotePath = 去尾斜杠目录 + '/' + 文件名），保存不再产生简写 |
| run_commands | `commands[]`（非空）、`timeoutSec`（默认 10）、可选 `protocol` | recover 同结构 |
| recover | 同 run_commands | 语义标注"重启后成功判定检测" |
| reboot | 仅可选 `protocol` | 无其他参数（命令序列引擎内置） |

`protocol` 过滤下拉值：**不限（空串）** / ftp / sftp / telnet / ssh（deploy 步骤语义=匹配 FTP/SFTP 端点；命令/重启类=匹配 Telnet/SSH 端点；文案在表单注明）。

## 3. 对话框结构

```
┌ TaskTemplateEditorDialog ────────────────────────────┐
│ 名称[必填]  描述[____]  标签[逗号分隔]  版本[int]      │
│ 目标设备: ┌ 多选列表（本机档案 ∪ 模板既有 deviceIds）┐ │
│           │ ☑ PLC-A (192.168.20.1)                 │ │
│           │ ☑ 导入体-x (device-…)（本机无档案）      │ │
│           └────────────────────────────────────────┘ │
│ 步骤: ┌列表┐  [＋添加] [－删除] [↑] [↓]               │
│       │1 部署│  右侧按类型切换参数面板（§2 契约）      │
│       │2 重启│  deploy: 远程目录+条目表+添加文件/目录… │
│       └────┘  commands/recover: 多行命令+timeoutSec   │
│               reboot: 仅 protocol                     │
│                        [保存] [取消]                   │
└──────────────────────────────────────────────────────┘
```

- 输入/输出都是完整 `TaskTemplate`：`TaskTemplateEditorDialog(const TaskTemplate&, QWidget*)` + `bool collect(TaskTemplate*)`；`unknownFields` 与未触及字段原样携带回存（前向兼容不丢）。
- 目标设备列表：本机档案（registry->list()）∪ 模板 deviceIds；不在册的条目名显示 `device-…（本机无档案）`，勾选默认保留（**不强制剥离**，保护 v2.13 悬空引用语义）；registry 为空时仅显示模板既有 id。
- deploy 条目表工具条 [添加文件…]（getOpenFileNames）/ [添加目录…]（getExistingDirectory），非原生对话框；remotePath 默认 = `remoteDirectory + '/' + 文件名`，表内可改。
- 无父窗口依赖：不访问 ConfigStore/协议库，只做表单 ↔ TaskTemplate 结构转换。
- 校验暴露为纯方法 `QString validate() const`（返回空串=通过，非空=中文原因）；accept 按钮槽内先跑 validate，非空弹框停留。测试可直调 validate 与 collect，无需模态布防。

## 4. 保存/编辑语义

- **新建**：传入空 TaskTemplate → collect 后 templateId 仍空 → `store.save()` 生成新稳定 ID（既有行为）。
- **编辑**：携带原 templateId 原位覆盖；`version` 为可编辑整数字段（默认显示原值，**不自动 bump**；store 降级闸仅拒 version 变小，等值放行）。
- 保存前校验链（按序）：`validateTaskTemplate`（名称/版本≥1/步骤非空/敏感键）→ deploy 条目预检（任一条 localPath 或 remotePath 为空 → 中文错误"步骤 N（文件部署）存在缺少路径的条目"，与引擎 parse 文案同口径）→ commands 逐行 trim 去空（全空 → 拒绝"至少一条命令"）。任一失败：QMessageBox 中文原因，停留对话框不丢编辑内容。
- 对话框 accept 前完成校验；TaskCenterWidget 收到 Accepted 后 `store.save(collected)`；save 返回 false（store 层告警兜底）→ 中文错误框，列表不刷新。
- 成功后 `refreshTemplates()` + 尽量回选被保存的模板 + `logMessage`（只记模板名与步骤数，无内容）。

> 勘误（2026-10-18）：本节校验文案已由 v2.14 #49-3 单源至 `TaskStepValidation.h`（引擎/编辑器共用唯一口径）——commands 全空拒绝文案实况为「步骤 N（…）缺少命令列表」（原「至少一条命令」），deploy 条目预检实况前缀为「步骤 N（文件部署）参数非法：…」（原「存在缺少路径的条目」）。历史正文不改写，以本注记为准。

## 5. 删除（store.remove + UI）

- `bool TaskTemplateStore::remove(const std::string& templateId)`：空 id → false；`ConfigStore::remove("task.template", key)` 转发返回值（模式对齐 DeviceRegistry::remove 的简化版；本表无旧行回退，无需清扫逻辑）。
- UI：[删除] 未选中禁用；点击 → QMessageBox::question「确定删除模板「X」（N 个步骤）？删除不影响历史执行记录。」**默认按钮「否」**；确认 → store.remove → refreshTemplates 复位；失败（false）→ 中文错误框。
- 执行历史为不可变快照（TaskRunTypes 既有语义），删除模板不级联、不禁止后续查看历史。

## 6. 测试（TDD）

`tst_task_template_store` +2：remove 成功（再 load 空、list 少一）；remove 不存在 id / 空 id → false。
`tst_task_center_widget`（对话框经 findChild 直操，无模态布防需求——collect 直调）扩 7：
1. 新建保存 → store 列表 +1、id 自动生成；
2. 编辑改 commands → 重读一致、version 未动；
3. 简写归一化：模板存 `files[]+remoteDirectory` → 编辑打开 → collect 出 items[]（remotePath 拼接正确、无 files 键）；
4. 悬空 deviceIds：列表显示"(本机无档案)"且 collect 不改写；
5. unknownFields 往返保留；
6. 删除三态：确认→列表-1、取消→不变、未选中按钮禁用；
7. 校验拒绝：空名/空命令/条目缺 localPath → collect false 且不落库。
`tst_task_center_e2e` 加一条链：新建模板（含 deploy+reboot 两步）→ 保存 → startTemplate 执行成功（走 Fake 引擎缝）。

## 8. 已拍板决策记录

| 决策 | 结论 | 否决项与理由 |
|---|---|---|
| 方案形态 | B 任务中心编辑器 | A 部署侧捕获只产得出 deploy 模板且是一次性胶水；C 不减 B 工作量 |
| 删除入口 | 并入本票 | 用户裁定（管理三腿一次配齐，成本低） |
| 编辑形态 | 独立对话框 | 中栏内联会把 1200+ 行 widget 推向不可维护 |
| 版本策略 | 可编辑整数，不自动 bump | 自动 bump 与 store 降级闸纠缠，用户要的是"改内容"不是"出版本" |
| 悬空 deviceIds | 保留可勾选，不强制剥离 | 保护 v2.13 跨机"先带模板后建档"语义 |
| 简写 files[] | 只读兼容，打开即归一 items[] | 双口径长期并存必然漂移 |
| unknownFields | 对话框进出全量携带 | 前向兼容纪律（R7 系） |
