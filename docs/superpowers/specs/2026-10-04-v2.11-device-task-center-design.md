# DeviceForge v2.11 设备档案与现场任务中心设计规格

- 日期：2026-10-04
- 基线：v2.10.0（`main`，批量命令与部署后重启已发布）
- 目标版本：v2.11
- 状态：设计已确认，待实施计划

## 1. 目标与成功标准

v2.11 将现有的设备选择、文件部署、批量命令、部署后重启和结果报告组合为可复用的现场任务中心，并为设备增加稳定、可读、跨协议共用的名称。

成功标准：

1. 同一物理设备的 FTP、SFTP、SSH、Telnet、Modbus 等端点共享一个设备名称。
2. 用户可保存任务模板并重复执行，不必重复配置设备、文件、命令和重启参数。
3. 任务执行按设备和步骤记录状态，失败设备可以从失败阶段继续。
4. 日志、进度、CSV/HTML 报告同时显示设备名称和真实地址。
5. 密码仅由现有 DPAPI/ConfigStore 管理，不进入模板、日志或报告。
6. 现有单次部署和双栏文件操作保持兼容，不强迫用户改用任务模板。

## 2. 范围与非目标

### 2.1 本期范围

- 设备档案：名称、备注、标签、协议端点、凭证引用。
- 任务模板：设备集合、文件部署、批量命令、重启和恢复检查步骤。
- 执行引擎：步骤编排、设备级状态机、取消、超时、重试和失败恢复。
- 执行记录：模板快照、设备结果、步骤结果、错误分类和报告导出数据。
- 任务中心 UI：模板管理、执行确认、实时进度、历史查询和失败重试。

### 2.2 非目标

- 不引入云端/SaaS、多用户权限或项目空间。
- 不替换现有协议适配器，不绕过 `IProtocolAdapter`、`IDeployable` 或调度器。
- 不在本期实现完整资产管理、拓扑发现或自动化编排语言。
- 不删除现有 FTP/SFTP 双栏和单次部署入口。

## 3. 设备档案与统一身份

新增 `DeviceProfile` 业务概念，兼容现有 `DeviceInfo`：

- `deviceId`：稳定 UUID，设备档案主键。
- `name`：用户可读名称，例如“控制器-01”。
- `note`：现场备注。
- `tags`：可选标签，如“产线A”“测试机”。
- `endpoints`：同一物理设备的多个协议端点。
- `endpointKey`：`protocol + ip + port`，用于连接和结果匹配。
- 凭证引用：只保存 ConfigStore/DPAPI 中的引用，不保存密码明文。

命名规则：

- 同一物理设备跨 FTP、SSH、Telnet 等协议共用名称。
- 名称为空时回退显示 `IP:端口`。
- 同一列表中的重复名称给出提示，但不强制全局唯一。
- 日志、进度和报告显示“名称 + IP:端口”，保证可读性和可排障性。

兼容规则：

- 现有 `DeviceInfo::alias` 映射为 `DeviceProfile::name`。
- 没有 `deviceId` 的旧配置按 `protocol + ip + port` 生成稳定 ID。
- 旧配置读取失败时回退现有设备列表，不阻断应用启动。

## 4. 任务模板

任务模板包含以下数据：

- 模板名称、描述、创建/更新时间、模板版本。
- 目标设备集合：手动选择、按标签选择或设备快照。
- 文件部署步骤：本地文件/目录、远程目标路径、FTP/SFTP、清理策略。
- 命令步骤：Telnet/SSH、多条有序命令、超时、重试。
- 重启步骤：协议、命令、超时、重试和是否等待恢复。
- 执行策略：串行/受控并行、失败后是否继续、失败阶段重试规则。

模板不保存密码。文件路径、目标路径和命令参数随模板保存；执行时解析当前设备档案和凭证引用。

模板执行前显示摘要，至少包括设备名称/IP、文件数量、命令数量、重启动作和风险提示。现有单次部署入口继续可用，并支持将当前配置保存为新模板。

## 5. 执行状态机与恢复

单台设备执行状态：

```text
Pending → Validating → Deploying → Commanding → Rebooting → Recovering → Succeeded
```

异常状态：`Failed`、`Cancelled`、`Skipped`、`PartiallySucceeded`。

执行规则：

- 每台设备独立推进，单台失败不隐式覆盖其他设备结果。
- 文件已成功且校验一致时，恢复执行跳过文件部署。
- 命令按序号记录，已完成命令不重复发送。
- 重启导致的连接断开视为预期事件，进入恢复检查。
- 恢复检查失败只标记“重启后未恢复”，不自动重复执行危险命令。
- 失败重试从失败阶段开始，支持仅重试失败设备。
- 所有操作支持取消；取消后不再启动新的设备步骤。

## 6. 持久化与执行记录

继续使用 `ConfigStore`，建议使用以下逻辑类型：

- `device.profile`
- `task.template`
- `task.run`
- `task.run.device`
- `task.run.step`

每次执行保存不可变快照：执行 ID、模板 ID/版本、开始/结束时间、操作者、设备快照、步骤结果、错误分类、重试次数和软件版本。执行记录支持按时间、设备名称、模板和结果筛选，并提供历史清理策略，防止无限增长。

命令原文默认不写入日志；只记录命令序号、状态、耗时和脱敏摘要。密码不进入模板、日志、报告或错误文本。

## 7. 模块与依赖边界

```text
TaskCenterWidget
    → TaskExecutionEngine
        → DeviceRegistry
        → TaskTemplateStore
        → TransferScheduler
        → BatchCommandRunner
        → TaskRunStore
```

模块职责：

- `DeviceRegistry`：设备档案 CRUD、名称/标签/端点管理、旧 `DeviceInfo` 转换。
- `TaskTemplateStore`：模板保存、加载、复制、版本化和校验。
- `TaskExecutionEngine`：步骤编排、设备状态机、取消、超时、重试和恢复。
- `TaskRunStore`：执行记录、历史查询、清理和报告数据。
- `TaskCenterWidget`：模板、设备选择、确认、实时进度和历史交互。

UI 不直接访问协议库；FTP/SFTP/Telnet/SSH 继续经现有适配器、`TransferScheduler` 和 `BatchCommandRunner` 完成。

## 8. UI 入口

主窗口新增“设备档案”和“任务模板”入口。任务模板页面采用三栏结构：

- 左栏：模板列表、搜索和标签筛选。
- 中栏：模板步骤和执行参数。
- 右栏：目标设备、最近结果和操作按钮。

执行中显示任务总进度、设备进度、当前阶段、耗时和日志，支持暂停/取消。执行后提供“从失败阶段重试”“导出报告”“复制任务为新模板”。危险操作（清理目录、重启、危险命令）使用明确的确认提示。

设备列表优先显示名称，地址作为次级信息；悬停可查看协议端点和备注。

## 9. 测试与验收

### 9.1 单元测试

- 设备别名、稳定 ID、端点合并和旧配置兼容。
- 模板序列化、版本升级和敏感字段排除。
- 执行引擎步骤顺序、取消、超时、重试、部分成功和失败恢复。
- 执行记录完整性、筛选、清理和报告数据。

### 9.2 集成测试

- 部署 → 命令 → 重启 → 恢复检查完整闭环。
- 多协议端点共享设备名称。
- 失败设备从失败阶段恢复，不重复成功步骤。
- 现有 FTP/SFTP、批量命令、双栏操作回归。

### 9.3 验收指标

- 模板可保存、重新打开并执行。
- 设备名称在设备列表、进度、日志、CSV/HTML 报告中一致显示。
- 失败设备可单独重试，成功设备不重复执行。
- 应用重启后设备档案、模板和历史记录可恢复。
- 密码和敏感命令信息不出现在持久化明文和日志中。
