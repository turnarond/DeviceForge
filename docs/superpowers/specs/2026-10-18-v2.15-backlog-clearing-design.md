## 2. 波1 设计

### 2.1 ConfigStore 截断根治（#49-5）

**取证基线**：生产 `store.list(...)` 调用点 28 处（SettingsDialog 3 / DeviceRegistry 4 / TaskRunStore 7 / TaskTemplateStore 1 / Modbus 4 / NetRelay 1 / OpcUa 1 / Telnet 1 / WebSocket 2 / DeviceBus 3 / 其余为显式分页器）。绝大多数调用方语义是"遍历全表"，limit 默认 1000 是**潜在数据丢失**而非防护。

**决策（方案甲，成本曲线否决了 forEachRow 大迁移）**：
- `list()` 签名改为 `limit = -1` 默认（-1 = 不下发 LIMIT、全表返回）；offset 默认 0 不动；显式传 limit 的调用方行为逐字不变（含 TaskRunStore `prune` 手写分页与 SettingsDialog 有意的 UI 限量）。
- 安全依据：本表为本地单机 SQLite，device.profile / task.run 族现实规模 ≤ 数千行，全表内存化与现 limit=1000 同量级，无 OOM 语义变化。
- **本波不迁清扫**（YAGNI）：`DeviceRegistry` 的 `list(type, 1000)` 显式参数保持，2.2 单独处理。

**红-绿锚**：既有 `store.list(type)` 无参调用在 >1000 行夹具下返回全部行（当前返回 1000——先红）；显式 limit 用例断言不变。

### 2.2 legacy device.list 清扫全量化（#49-8）+ 同型静默截断站点

`DeviceRegistry` 三处清扫/扫描显式 `1000` 上限：改为全表形态（不带 limit 参数走新默认）。清扫正确性用例升级：夹具造 >1000 行 legacy 残留，断言**一条不漏**地被清扫（当前实现漏扫——先红）。#49-8「分页」诉求以"全表遍历"兑现，裁定记由：表现实规模使分页属过度设计。

**同型站点（成文期取证补入，2.1 清点时发现）**：`TaskTemplateStore::list()`（TaskTemplateStore.cpp:223 `list(kRecordType, 1000)`）——超 1000 模板时冲突检测/编辑/删除静默不可见，与清扫同属"遍历全表语义被 limit 截断"缺陷类，一并迁移为全表形态并附 >1000 行可见性用例。`TaskRunStore`/`ModbusTargetStore`/各 Widget 的显式 limit 属有意限量或分页器，不动。

### 2.3 aggregateStatus 单源（#49-6）

新纯逻辑头 `src/task/TaskRunAggregate.h`：`taskrun::aggregateRunStatus(const TaskRunOutcome&)`——函数体自 `TaskCenterWidget::aggregateStatus`（TaskCenterWidget.cpp:741）原样搬移，Failed > Cancelled > Running > Success 优先级规则单源。生产侧成员函数保留为薄转发（既有调用点与测试引用不动）；`tst_task_center_e2e.cpp:322` **删除复制实现改 include 纯头**——复制漂移从机制上消除。规则用例进纯头直测（新增 tst_task_run_aggregate 目标或并入既有 task 系目标，计划阶段定），e2e 断言语义不变。

### 2.4 导入通道复用 saveUniqueByName（E）

`TaskTemplateStore` 导入冲突三分支现自实现，改走 `saveUniqueByName`（落库腿 + 冲突回调注入）。冲突 UI 与部署页「保存为模板」同组件形态（三按钮 QMessageBox，默认=改名），冲突扫描单点化。约束：**导入的既有用词语义逐条保留**（用例先行盘点，落库腿替换前后断言不缩水）；`NameConflictChoice` 枚举与回调签名如需扩展，在计划阶段先审后动。

### 2.5 telnet 工装 TIMEOUT（D）

`tests/CMakeLists.txt` 为 `tst_telnet_timeout` 增 `TIMEOUT 60` 属性——负载下挂起形态（v2.14.0 终验实踩，基线记忆 in册）从无限等待降为有界红。不改测试逻辑、不动 vendored lwcommunicate；分诊口径（命中按既有 flake 处理、单跑复核+全量复跑两遍）随波4 文档段回写。

## 3. 波2 设计：文件夹条目支持（中央裁定）

**现状**：单发部署与任务模板同走 TransferExecutor，目录源一律前置失败（v2.14.1 已钉桩）；`IDeployable::uploadFolder` 存在但全仓零调用；编辑器 teAddDir 添的目录条目执行必失败。

**候选与倾向**：
- **甲：入口递归展开（推荐倾向）**——单发 collect 与模板 deploy 步 items 在**入库/入任务前**把目录递归展开为普通文件条目（相对目录结构保留到 remoteDirectory 下），传输层语义不动、SylixOS 约束零触碰；代价：海量小目录展开后的条目数上限需裁定（拟 kMaxExpandedItems 常量+超限中文拒绝）。
- 乙：执行期引擎递归——TransferExecutor/通道扩目录语义，ABI 与全链路回归风险大。
- 丙：维持拒绝+UI 引导——零交付，现场"整目录部署"诉求不满足。

**正式裁定时点**：波2 设计节单独过用户（含 teAddDir 行为变更口径：展开发生在添加时还是执行装配时）。本规格锁定"三入口同口径、失败不留静默"为验收不变式。

## 4. 波3 设计：窄屏工具栏（B）

主窗口工具栏单行最小宽 ~2010px > 常见 1920 屏（v2.14 双屏诊断实测）。方向：换行/折叠/图标化组合，**先出 HTML 视觉稿过用户目再实现**（用户既有偏好），色值取项目主题文件。v2.14.1 的按屏钳制保留为兜底，本波解决"单屏也放不下"的正题。
