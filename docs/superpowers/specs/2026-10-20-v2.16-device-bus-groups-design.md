## 0. 摘要

设备栏（主窗口顶部胶囊行）在 30–80 台设备下不可用：胶囊是**裸 `QHBoxLayout`**，无滚动、无换行、无分组，设备一多就互相挤压变形。

**2026-10-20 视觉稿关卡后重画（用户看过第一版稿后给的方向，原"横向铺段"方案作废）**：分段铺开只是把溢出从"一行"推到"一段"——单段 24 台铺开照样放不下。本版形态是：

1. **第 1 行只显示"已选中的设备"**（chips），胶囊文案**只显名称、不带 `ip:port`**（重名时才追加 ip 短尾标）；
2. 其余全部设备收进一个 **「设备 ▾」`QMenu` 入口**：主菜单一行一个分组（组名 + 已选/总数，「未分组」即用户要的"默认分组"永远排在最后），**点开子菜单才是该组成员、勾选即选中**——子菜单本身就是一次折叠，"默认分组折起来"由结构天然满足，不需要折叠状态、也不需要持久化键；
3. **搜索框留在行尾**，作用是过滤下一次打开菜单时的可见项（不实时重开菜单）；
4. **双击 chips＝"打开这台设备"**（按该设备首个可解析端点的协议跳到对应工具页）；档案编辑入口收敛到右键菜单；
5. **未选择任何设备＝没有目标**，不再"默认对全部设备生效"（现场决定，用户 2026-10-20 指定；见 §6 变更清单——这条与任务模板执行链的既有口径一致，反而消除了两套语义并存）。

数据模型与磁盘格式**不变**，对外选择契约**不变**，ConfigStore **零新增键**。

### 2.1 `src/ui/DeviceBusGroups.h`（新，纯头，无 QWidget 依赖）

```cpp
namespace devicebus {

// 「未分组」是函数内 static，不用命名空间级 inline 变量：静态 QString 的动态初始化时机
```

**规则（逐条可测；折叠态相关的规则 3/4 随第一版方案作废，因为 `QMenu` 子菜单本身就是一次折叠，没有"用户折叠状态"要存）**

1. 一台设备有 N 个标签 → 在 N 个分组各出现一次；**无**标签或规范化后全空 → 只进「未分组」（默认分组）。
2. 组序：标签组按 `tag` 升序（**区分大小写**，与 SylixOS/POSIX 目录口径一致）；「未分组」**永远最后**。同组内按 registry 返回顺序（不新排序）。
3. `filterText` 非空时：组内只留命中设备（`deviceIds`），`total` 仍是不过滤的成员总数 ⇒ 菜单一项显示 `组名 命中数/总数`；**命中数为 0 的组不进菜单**（不是"折叠显示"，是压根不列——子菜单里没有东西可看是噪声）。
4. 全不命中（所有组命中数均为 0）：菜单只留一项不可点的说明行「无匹配设备（N 台）」，N=设备总数。
5. 「未分组」这一组**只有非空时才出现**（一台都不落默认分组时，菜单里不该有个空壳组）。

**边界（自检出）**：设备档案端点协议目前只允许 `ftp/ftps/sftp/ssh/telnet/modbus`（`DeviceBusWidget.cpp:40-44` `editableEndpointProtocols()`），**存不出 opcua 端点**——所以 `opcua` 那条路由在子项目 C（OPC UA 纳入统一设备/凭据）落地前是**不可达分支**。本规格仍保留该映射（纯头单测直接构造 profile 覆盖），但 §5 的 UI 级验收只覆盖四条可达协议，opcua 一条标注为"待 C 落地后转可达"，不得写成已端到端验证。

`DeviceBusWidget::openDeviceRequested(const DeviceProfile&)` → `DeviceForge::openDeviceAt(const DeviceProfile&)` 只做编排：`routeTo` → 切 `toolStack` → **按各页真实具备的能力做选中**（见下表，逐页实测），并写一条**脱敏**日志（设备名 + 协议 + 页名，无凭据）。信号载荷取 `DeviceProfile` 而非 `deviceId`：旧 `ip:port` 胶囊本就没有可用的持久 id，而 `editProfileFor` 已经在用 `fromDeviceInfo` 合成（`cpp:636-645`），复用同一段装配即可，无需第二条通道。

**每页"能不能被选中一台"实测（这条推翻了我上一版的 §5 验收第 3 条）**——全仓 `setDeviceBusWidget` 只有 **2 个**调用点（`DeviceForge.cpp:268` 部署页、`:323` 批量命令页），`selectedDevices()` 的消费方只有部署页：

### 2.3 UI 装配（`DeviceBusWidget` 第 1 行）

- **第 1 行 = 已选 chips + 入口 + 搜索**（横向 `QHBoxLayout`，**不再需要 `QScrollArea`**——已选集合本来就少，chips 行放不下时才由入口按钮兜底，见下条）：
  - `deviceRow` 依次是：设备图标 → **chips 容器**（只装已选设备胶囊，`objectName="selectedPillHost"`）→ 空态提示 `QLabel`（`objectName="deviceBusHint"`）→ 「设备 ▾」入口按钮（`objectName="devicePickerBtn"`，文本 `设备 ▾ 已选 N 台` / N=0 时 `设备 ▾ 未选择`）→ 行尾搜索框 → `+ 添加`按钮（现状保留）。
  - **chips 只显名称**：去掉 `pillCaption`（`cpp:82-87`）里的 `ip:port` 段；`name` 为空时**仍回落成 `ip:port`**（否则栏里出现空白胶囊，比长更糟）。tooltip 继续带逐端点 `协议 ip:port` + 备注（`profileToolTip` 现成）。
  - **重名才加尾标**：当且仅当该名称在档案里重复（判据口径与 `DeviceRegistry::rebuildWarnings` `:310-320` 同源，别另造一套）时，chips 文本追加短尾标 `名称 ·ip`。判定集合在 `rebuildRows()` 里算一次，逐胶囊查表，不在胶囊构造里重复扫描。
- **「设备 ▾」弹层 = 每次 `aboutToShow` 现建的 `QMenu`**（分组即子菜单，勾选即选中）：
  - 主菜单：一行一个分组项 `组名 命中数/总数`，`addMenu(submenu)` 展开成员；成员项是 `QAction`（`setCheckable(true)`，`checked` == 该设备在选中集合里）；「未分组」项排最后；组内成员顺序 = registry 顺序。
  - 底部固定两项（分隔线之后）：`全选` 与 `清空选择`。**不做 `仅选本组`／`本段反选`（YAGNI：子菜单本身就是逐组操作的范围）**。这两项作用于**当前过滤可见**的设备——过滤词非空时"全选"只全选得着的那些，这条语义必须写死并在菜单项文案上说出来（`全选可见 12 台`），否则用户会以为漏了。
  - 菜单不持久化、不记忆展开态；关闭即弃（每次 `aboutToShow` 重建，成本 = 一次 `segments()`）。成员极多的单组（例：50 台同标签）由 `QMenu` 内容超出屏幕高度时 **Qt 内建的上下滚箭头**兜住——**这是结构性的，不是我们实现的**：实读本地 `qmenu.h`（235 行）`grep -in scroll` **零命中**，公开 API 没有任何可调滚动项，所以本规格**不承诺"可调滚动行数"**，只承诺"不会横向溢出"，超限表现由任务 0 视觉稿标注 + 任务 4 用例如实登记（能不能限高、限多少属实现期实测，不许预支）。
- **chips 交互**：左键单击＝取消选中（chips 的存在本身就等于选中，点击语义只能是移出）；双击＝**打开这台设备**（`eventFilter` 里现有的 `editProfileFor` 分支改发射 `openDeviceRequested(profile)`）；右键菜单三项**按此次序**＝「打开这台设备 ／ 编辑档案 ／ 移除设备」。置顶项是这次语义变更的**自解释器**——老用户双击发现行为变了，右键一看就知道新含义叫什么、老含义搬去了哪；只做右键不做双击的话新能力会长期无人使用。编辑档案退到第二项但**能力零丢失**（`cpp:589-591` 的显示门槛是 `m_registry` 而非 `deviceId`，生产里 `DeviceForge.cpp:90` 恒注入非空，旧 `ip:port` 胶囊也照样有该项）。
- **`allDevices()` 必须仍是全量**（硬线）：chips 只是"已选"的视图，设备全集另存（现有 `m_devices` 保持全量重建），批量命令页（`TelnetWidget.cpp:252`）与部署页下拉填充（`FtpDeployWidget.cpp:1543`）照旧拿到 80 台。**已选 chips 少挂不是事故，把 `m_devices` 一起少挂才是**。
- 重建走 `blockSignals(true)` 窗口 + 末尾一次性 `emit deviceSelectionChanged()`（与波3 编辑器批量刷表同法；菜单里连勾 5 台也只广播一次）。
- 样式：chips 沿用 `#devicePill`（现成两主题节）；入口按钮与空态提示复用现有 token（石墨边、琴色只用于信号态）；`QMenu` 本体样式现成（`darkstyle.qss:423-438` 系），**本版预计零新增 QSS 节**——若入口按钮需要定宽再补，视觉稿上先标"沿用现有 `QPushButton` 通用节"。

### 2.4 契约保持不变（硬线）

`selectedDevices()`、`selectedDeviceProfiles()`、**`allDevices()`**、**`user()` / `password()`**、`deviceSelectionChanged()`、`deviceProfileEdited()` 的**签名与返回类型一字不改**；本版只**新增**一个信号 `openDeviceRequested(const DeviceProfile&)`（纯加法，声明加在类末尾）。

**实现内部必须换掉一条既有机制**（这是本形态带来的、规格里必须写清的一处）：`selectedDevices()`/`selectedDeviceProfiles()` 现在按 `m_devices[i]` ↔ `m_pills[i]` **位置配对**推断"哪些台被选中"（`cpp:796-823`）。chips 形态下 `m_pills` 只装已选、`m_devices` 仍是全量，位置配对从机制上失效 ⇒ 选中态改为**显式 id 集合**（`QSet<QString> m_selectedIds`，legacy 无 id 行退化成 `ip:port` 键），两个访问器按该集合从 `m_devices` 取。多标签设备在菜单里出现多次也只对应集合里的一个 id ⇒ **去重由结构保证**，不再需要显示层去重补丁。

消费方影响面（**逐 API 实读，不抄二手清单**）：只有部署页读选中（`FtpDeployWidget.cpp:884`/`:1368`），Telnet 走 `allDevices()`（`TelnetWidget.cpp:252`）与选中无关，MODBUS 未接总线。⇒ 过滤、菜单展开状态、chips 多少**绝不能**改变 `allDevices()` 返回内容。刷新路径仍须保住已选集合（v2.14 Important-4 的语义不得退化——那条修复本身就是"重建不得清空选中"）。

### 2.5 持久化

**本版 ConfigStore 零新增键**（第一版方案的 `device.bus.collapsedTags` 随折叠持久化一起作废：子菜单的折叠是结构性的，没有用户状态要存）。搜索串是会话态，不持久化。磁盘格式（`device.profile` 记录结构、`tags` 字段形态）不动 ⇒ 无迁移、无旧数据不可读。

## 3. 异常态（逐条定死）

1. 旧 `ip:port` 无档案行：进「未分组」（默认分组）；双击＝按合成档案的单端点路由（协议列为空则 ftp 兜底，§2.2）；右键菜单三项**照常齐全**——「编辑档案」的显示门槛是 `m_registry` 判空（`cpp:589-591`）而非 `deviceId`，生产恒非空（`DeviceForge.cpp:90`），编辑走 `cpp:636-645` 现成的 `fromDeviceInfo` 合成路径。**已核实：双击让位不丢任何编辑能力**（我上一版把这里写成"评审必查项：可能造成无处可及"，前提不成立，降级为一条回归用例：旧行胶囊右键「编辑档案」必须仍然可达并保存成功）。
2. 标签含首尾空格 / 空串 / 纯分隔符：`normalizeTag` 后为空即不算标签 → 落「未分组」。
3. 大小写不同标签（`车间A` / `车间a`）：两个组，不合并。
4. 搜索无命中：菜单里只留一行不可点的说明「无匹配设备（N 台）」，N=设备总数；**既有选择绝不清空**（过滤只是视图）。
5. **未选择任何设备 ⇒ 没有目标**（本版行为变更，用户 2026-10-20 指定）：chips 行为空 + 空态提示「未选择设备——点「设备 ▾」选目标」；部署页执行路径删除 `if (devices.empty()) devices = allDevices()` 兜底（`FtpDeployWidget.cpp:885`），改为拒绝并给一条日志「未选择目标设备，请在设备栏选择至少一台」；按钮文案同步改（`:1369` 空时显示「▶ 部署（未选择设备）」）。**这条把单发部署拉到与任务模板执行链同口径**（后者一直是空目标即拒绝：`TaskCenterWidget.cpp:464`、`TaskExecutionEngine.cpp:371`/`:953`、`FtpDeployBackend.cpp:155`），并让手册里"两套语义并存"的对比句失效（`:113`、`:130` 同批改实）。
6. **重名设备**：名称在档案里重复时（判据与 `DeviceRegistry::rebuildWarnings:310-320` 同源），chips 与菜单项文本追加 `·ip` 短尾标；不重名则只显名称。名称为空的档案**回落显 `ip:port`**（`pillCaption` 现成行为），保证栏里不出现空白胶囊。
7. **已选太多导致行宽不够**（全选 80 台必然发生）：chips 只显能放下的前若干枚，其余折成一枚 `+M 台` 按钮（`objectName="devicePillMore"`），点击打开**同一个**「设备 ▾」菜单。可见枚数由 `widthForHeight`/尺寸事件算，**不承诺固定枚数**；用例只断"折起来的数量 + 可见数量 == 选中总数"与"点 `+M 台` 出的是同一个菜单"，不断具体枚数（屏宽相关判据一律走 `tests/AGENTS.md` 约定第 6 条）。
8. 80 台 × 平均 2 标签：菜单每次 `aboutToShow` 一次性构建（`segments()` 一遍 + 逐项 `addAction`），禁止逐项触发选中广播；勾选多台的广播计数由 `blockSignals` 窗口钉死为 1（**不承诺 wall-clock 毫秒数**——本机测不稳的指标不写进验收）。
9. 目标页尚未创建/懒建（任务中心、设置）：`openDeviceAt` 只走导航已注册的页；`Page::None` 见 §2.2。
10. 日志脱敏：只记设备名/协议/页名/计数，不记凭据与端点口令。

## 4. `normalizeTag` 单源化（含一项必须显性交代的行为变更）

**实测后收窄的改动点**（本条初稿写"读写两侧 + 保存切分 + 圈选四处全部改用 `normalizeTag`"，取证后发现其中三处**现状已经在做等价 trim**，真改动只有一处）：

| 站点 | 现状（实读） | 本版动作 | 是否用户可见 |
|---|---|---|---|
| `DeviceRegistry::normalize`（`src/device/DeviceRegistry.cpp:111-113`，作用于 `upsert:161` / `saveReplacing:195`） | 已 `trim(tag)` + `appendUnique`（`:67-71` 要求 `!value.empty()`）⇒ 档案标签**存库前就去了首尾空白、空串已被丢弃** | 把 `trim` 换成 `devicebus::normalizeTag`——**行为等值的单源化**，不多不少 | 否 |
| 档案对话框标签切分（`src/ui/DeviceBusWidget.cpp:200-204`，`m_tagsEdit` 逗号切分） | 已 `tag.trimmed()` 且跳空 | 同上换调用，等值 | 否 |
| `DeviceProfileCodec` 读侧（`src/device/DeviceProfileCodec.cpp:67-68`） | **不 trim**（原样入 `profile.tags`） | **不改**：库里数据是写入时 normalize 过的；在读侧再改一次等于造第二条真源、还会让"读到的"和"存的"不一致 | 否 |
| 模板圈选（`TaskCenterWidget::resolveTargets` `src/task/TaskCenterWidget.cpp:390-398`，`std::find` 精确相等） | `task.tagSelectors` 取自模板 JSON，**从未 trim** | **唯一真改动**：比较前对 selector 与 `profile.tags` 两侧都 `normalizeTag` | **是**（见下） |

- 范围刻意收窄：**只去首尾空白、只把空串剔除**。不改大小写、不折叠内部空格、不做全半角转换——避免"顺手优化"改变匹配语义。

- 按新判据这仍属 **MINOR**（无需用户改配置），不升 MAJOR。

## 8. 不做清单（明示 YAGNI）

- 设备级连接状态、心跳、在线检测（"真会话"）——本次双击只是导航入口。**就实一句**：这条线在仓里已经是"有钩子、无数据源"的形态——`DeviceBusWidget::setOnlineStatus(ip, online)`（`cpp:831-841`）**全仓零调用方**（`grep -rn setOnlineStatus src/ tests/` 只有声明与定义两条命中），胶囊的 `online` 属性除该函数外无人设置，于是两套 QSS 的 `#devicePill[online="true"/"false"]` 左边框规则（`darkstyle.qss:676-677` / `darkstyle-light.qss:676-677`）**当前永不命中**。本规格不去接它（没有可靠的在线数据源，接了就是假信号），但视觉稿不得画上线状态色条，手册也不得写"设备栏显示在线/离线"。
- 可保存的"选择集/设备方案"（与 `tagSelectors` 能力重叠）。
- **多标签设备在多个子菜单里各出现一次，勾选状态跨组实时联动**——本版**不做**（代价：勾了 A 组再看 B 组，同一台在两处显示不一致的勾选态，直到菜单重建才对齐）。正确性由 §2.4 的显式 `m_selectedIds` 兜住：一台设备无论在哪几个组被勾到，选中集合里只有一个 id，执行目标集绝不会翻倍。要做联动就得让每个 `QAction` 监听集合并刷自己，属额外的状态同步面，本版按 YAGNI 不做，但**必须在稿上把这个不一致画出来并写明**（不是藏起来）。
