## 0. 摘要

设备栏（主窗口顶部胶囊行）在 30–80 台设备下不可用：胶囊是**裸 `QHBoxLayout`**，无滚动、无换行、无分组，设备一多就互相挤压变形。本设计不推翻横向形态，而是：

1. 胶囊行按**标签（`DeviceProfile.tags`）分段**显示，段头可折叠；
2. 常驻**搜索框**（名称 / IP / 标签三源命中）；
3. **双击胶囊＝"打开这台设备"**：按该设备首个可解析端点的协议跳到对应工具页并选中它；档案编辑入口收敛到右键菜单；
4. 标签规范化（`normalizeTag`）单源化，同时修掉"模板按标签圈选时带首尾空格的标签静默匹配不上"的缺陷。

数据模型与磁盘格式**不变**，选择契约**不变**，三个消费方**零改动**。

## 2. 组件与边界

```
DeviceRegistry ──list()──► DeviceBusWidget（UI 装配）
                                │
                                ├─► DeviceBusGroups.h  （纯头：分段/排序/过滤/折叠）
                                └─► DeviceOpenRouter.h （纯头：profile → 目标工具页）
                                       │
DeviceForge::openDeviceAt(deviceId) ◄───┘  （切页 + 让目标页选中该设备）
```

### 2.1 `src/ui/DeviceBusGroups.h`（新，纯头，无 QWidget 依赖）

```cpp
namespace devicebus {

inline const QString kUngroupedTag = QStringLiteral("未分组");   // 仅 UI 段名，绝不写回 tags

struct Segment {
    QString tag;            // 规范化后的标签；未分组段为 kUngroupedTag
    QStringList deviceIds;  // 段内成员，按 registry 顺序
    bool collapsed = false; // 未命中段自动折叠；未分组段可折叠
    bool autoCollapsedBySearch = false; // 搜索临时折叠，区别于用户主动折叠
};

// 唯一分类真源：
// segments(profiles, collapsedTags, filterText) -> QList<Segment>
QList<Segment> segments(const std::vector<DeviceProfile>& profiles,
                        const QSet<QString>& collapsedTags,
                        const QString& filterText);

QString normalizeTag(const QString& raw);   // 去首尾空白；空/纯分隔符 → 空串（=不算标签）
bool matchesFilter(const DeviceProfile& p, const QString& filterText); // 名称/IP/标签，子串、大小写不敏感
}
```

**规则（逐条可测）**

1. 一台设备有 N 个标签 → 在 N 个段各出现一次；**无**标签或规范化后全空 → 只进「未分组」。
2. 段序：标签段按 `tag` 升序（**区分大小写**，与选择集合与 SylixOS/POSIX 目录口径一致）；「未分组」**永远最后**。同段内按 registry 返回顺序（不新排序）。
3. `filterText` 非空时：段内只留命中设备；**无命中的段整段折叠**（`autoCollapsedBySearch=true`）；命中段自动展开（覆盖用户折叠态，但**不改写**持久化的 `collapsedTags`）。
4. `collapsedTags` 里不存在于当前标签集合的键 → 直接丢弃（不报错、不残留）。
5. 段头计数：`显示数/段内总数`（折叠时只显示段内总数）。

### 2.2 `src/ui/DeviceOpenRouter.h`（新，纯头）

```cpp
namespace deviceopen {
enum class Target { FtpDeploy, BatchCommand, Modbus, OpcUa, None };
// 取 endpoints 中首个"协议可解析且非空 ip"的端点决定目标页（与任务链"首个可解析端点"口径同源）
Target routeTo(const DeviceProfile& profile);
}
```

| 端点协议 | 目标页 |
|---|---|
| `ftp` / `ftps` / `sftp` | 文件部署（导航 index 0） |
| `telnet` / `ssh` | 批量命令（index 1） |
| `modbus` | MODBUS（index 3） |
| `opcua` | OPC UA（index 5） |
| 无档案旧行（`ip:port`） | 按 `ftp` 默认（不报错） |
| 协议不可识别 / 无端点 | `Target::None`：**不切页**，状态栏提示「该协议暂无对应工具页」 |

**边界（自检出）**：设备档案端点协议目前只允许 `ftp/ftps/sftp/ssh/telnet/modbus`（`DeviceBusWidget.cpp:40-44` `editableEndpointProtocols()`），**存不出 opcua 端点**——所以 `opcua` 那条路由在子项目 C（OPC UA 纳入统一设备/凭据）落地前是**不可达分支**。本规格仍保留该映射（纯头单测直接构造 profile 覆盖），但 §5 的 UI 级验收只覆盖四条可达协议，opcua 一条标注为"待 C 落地后转可达"，不得写成已端到端验证。

`DeviceForge::openDeviceAt(const QString& deviceId)` 只做编排：`routeTo` → 切 `toolStack` → 让目标页选中该设备（复用各页现有 `setDeviceBusWidget` / 选择同步路径），并写一条**脱敏**日志（设备名 + 协议 + 页名，无凭据）。

### 2.3 UI 装配（`DeviceBusWidget` 第 1 行）

- 外层：**横向 `QScrollArea`**（`widgetResizable=false`、竖向关、水平滚轮可横滚——`setHorizontalScrollBarPolicy(AlwaysOff)` + `viewport` 滚轮事件转水平滚动）；内层容器仍是 `QHBoxLayout`（分段容器）。
- 段头：`QPushButton`（`objectName="deviceTagHeader"`，`deviceTag` 属性=标签串），文本 `标签名 n/m ▾/▸`；左键＝切折叠；右键菜单＝「本段全选 / 本段反选 / 全部折叠」。
- 搜索：行尾常驻 `QLineEdit`（`objectName="deviceSearchEdit"`，占位「搜索 名称 / IP / 标签」），实时过滤、**不持久化**（会话态，重启后为空）。
- 重建走 `blockSignals(true)` 窗口 + 末尾一次性 `emit deviceSelectionChanged()`（与波3 编辑器批量刷表同法；「本段全选」也只广播一次）。
- 样式：段头与胶囊只用纯色 + 1px 边框，色值取自 `darkstyle.qss` / `darkstyle-light.qss` 现有 token（石墨边、琴色只用于信号态），双主题各加一节；QSS 不支持渐变与阴影，不得在稿里承诺。

### 2.4 契约保持不变（硬线）

`selectedDevices()`、`selectedDeviceProfiles()`、**`allDevices()`**、**`user()` / `password()`**、`deviceSelectionChanged()`、`deviceProfileEdited()` 的签名与语义一字不改；选中集合按 `deviceId` **去重**（多段重复显示不影响集合）。三个消费方零改动——注意 Telnet 走 `allDevices()`（与选中态无关），过滤/折叠**绝不能**改变它返回的集合内容。刷新路径仍须保住已选集合（v2.14 Important-4 的语义不得退化）。

### 2.5 持久化

ConfigStore（**禁** QSettings）：仅新增 `device.bus.collapsedTags`（QStringList，缺键＝全展开）。搜索串不持久化。

## 3. 异常态（逐条定死）

1. 旧 `ip:port` 无档案行：进「未分组」；右键**无**「编辑档案」（沿用 `m_registry` 判空现状）；双击按 ftp 路由。
2. 标签含首尾空格 / 空串 / 纯分隔符：`normalizeTag` 后为空即不算标签 → 落「未分组」。
3. 大小写不同标签（`车间A` / `车间a`）：两个段，不合并。
4. 搜索无命中：段头区显示一行提示「无匹配设备（N 台已隐藏）」，**既有选择绝不清空**。
5. 折叠态含已删标签：加载时丢弃（§2.1 规则 4）。
6. 80 台 × 平均 2 标签（约 6 段）：重建必须一次批量挂载，禁止逐行回调（用"批窗口内信号计数为 0 + 段头一次刷新"钉死；**不承诺 wall-clock 毫秒数**——本机测不稳的指标不写进验收）。
7. 目标页尚未创建/懒建（任务中心、设置）：`openDeviceAt` 只走导航已注册的页；`Target::None` 见 §2.2。
8. 日志脱敏：只记设备名/协议/页名/计数，不记凭据与端点口令。

## 4. `normalizeTag` 单源化（含一项必须显性交代的行为变更）

改动点：`DeviceProfileCodec` 读写两侧 + 档案对话框保存时切分标签 + `TaskCenterWidget.cpp:390-398` 的圈选匹配，全部改用 `devicebus::normalizeTag`（模板侧对 `tagSelectors` 与 `profile.tags` **两侧都规范化后再比较**）。

- 范围刻意收窄：**只去首尾空白、只把空串剔除**。不改大小写、不折叠内部空格、不做全半角转换——避免"顺手优化"改变匹配语义。
- 后果：形如 `" 车间A "` 的标签**过去静默匹配不上**，今后匹配得上 ⇒ **某些既有模板的实际部署目标集可能变大**。这是"从漏到不漏"，但属现场可见变更，必须：① 红测钉住该行为（不是意外后果）；② 写进 v2.16 发布说明；③ 手册标签小节补一句口径说明。
- 按新判据这仍属 **MINOR**（无需用户改配置），不升 MAJOR。
