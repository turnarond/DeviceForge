## 0. 摘要

设备栏（主窗口顶部胶囊行）在 30–80 台设备下不可用：胶囊是**裸 `QHBoxLayout`**，无滚动、无换行、无分组，设备一多就互相挤压变形。本设计不推翻横向形态，而是：

1. 胶囊行按**标签（`DeviceProfile.tags`）分段**显示，段头可折叠；
2. 常驻**搜索框**（名称 / IP / 标签三源命中）；
3. **双击胶囊＝"打开这台设备"**：按该设备首个可解析端点的协议跳到对应工具页并选中它；档案编辑入口收敛到右键菜单；
4. 标签规范化（`normalizeTag`）单源化，同时修掉"模板按标签圈选时带首尾空格的标签静默匹配不上"的缺陷。

数据模型与磁盘格式**不变**，选择契约**不变**，三个消费方**零改动**。

### 2.1 `src/ui/DeviceBusGroups.h`（新，纯头，无 QWidget 依赖）

```cpp
namespace devicebus {

inline const QString kUngroupedTag = QStringLiteral("未分组");   // 仅 UI 段名，绝不写回 tags

struct Segment {
    QString tag;            // 规范化后的标签；未分组段为 kUngroupedTag
    QStringList deviceIds;  // 段内成员，按 registry 顺序
    bool collapsed = false; // 未命中段自动折叠；未分组段可折叠
    bool autoCollapsedBySearch = false; // 搜索临时折叠，区别于用户主动折叠
};

// 唯一分类真源：
// segments(profiles, collapsedTags, filterText) -> QList<Segment>
QList<Segment> segments(const std::vector<DeviceProfile>& profiles,
                        const QSet<QString>& collapsedTags,
                        const QString& filterText);

QString normalizeTag(const QString& raw);   // 去首尾空白；空/纯分隔符 → 空串（=不算标签）
bool matchesFilter(const DeviceProfile& p, const QString& filterText); // 名称/IP/标签，子串、大小写不敏感
}
```

**规则（逐条可测）**

1. 一台设备有 N 个标签 → 在 N 个段各出现一次；**无**标签或规范化后全空 → 只进「未分组」。
2. 段序：标签段按 `tag` 升序（**区分大小写**，与选择集合与 SylixOS/POSIX 目录口径一致）；「未分组」**永远最后**。同段内按 registry 返回顺序（不新排序）。
3. `filterText` 非空时：段内只留命中设备；**无命中的段整段折叠**（`autoCollapsedBySearch=true`）；命中段自动展开（覆盖用户折叠态，但**不改写**持久化的 `collapsedTags`）。
4. `collapsedTags` 里不存在于当前标签集合的键 → 直接丢弃（不报错、不残留）。
5. 段头计数：`显示数/段内总数`（折叠时只显示段内总数）。

### 2.2 `src/ui/DeviceOpenRouter.h`（新，纯头）

```cpp
namespace deviceopen {
enum class Page { FtpDeploy, BatchCommand, Modbus, OpcUa, None };
struct Route {
    Page page = Page::None;
    QString protocol;   // 命中的端点协议（选中/日志用）
    QString ip;         // 命中的端点 ip —— 部署页设备下拉的键就是 ip 文本，路由与选中必须同源
    int port = 0;
};
// 取 endpoints 中首个"协议可解析且非空 ip"的端点决定目标页与选中键（与任务链"首个可解析端点"口径同源）
Route routeTo(const DeviceProfile& profile);
}
```

| 端点协议 | 目标页 |
|---|---|
| `ftp` / `ftps` / `sftp` | 文件部署（导航 index 0） |
| `telnet` / `ssh` | 批量命令（index 1） |
| `modbus` | MODBUS（index 3） |
| `opcua` | OPC UA（index 5） |
| 无档案旧行（`ip:port`） | 合成档案只带单端点（`DeviceRegistry.cpp:94-102`），协议列取自 `device.list`；**该列为空或不可识别时按 `ftp` 兜底**（与编辑器现有兜底 `DeviceBusWidget.cpp:254` `未知/空 → ftp` 同口径），不报错、不判 `None` |
| 协议不可识别 / 无端点（**有档案**的设备） | `Page::None`：**不切页**，状态栏提示「该设备没有可用的协议端点」。**判定口径（2026-10-20 定，写计划时发现的歧义）**：`routeTo` 逐个端点扫描，遇"ip 为空"或"协议不认识"的端点**跳过继续找下一个**，整条档案一个可用端点都没有才判 `None`——多端点档案（例：`[{ip:"", telnet}, {ip:"10.2.3.4", modbus}]`）应落到 MODBUS 而不是判无可用页 |

**边界（自检出）**：设备档案端点协议目前只允许 `ftp/ftps/sftp/ssh/telnet/modbus`（`DeviceBusWidget.cpp:40-44` `editableEndpointProtocols()`），**存不出 opcua 端点**——所以 `opcua` 那条路由在子项目 C（OPC UA 纳入统一设备/凭据）落地前是**不可达分支**。本规格仍保留该映射（纯头单测直接构造 profile 覆盖），但 §5 的 UI 级验收只覆盖四条可达协议，opcua 一条标注为"待 C 落地后转可达"，不得写成已端到端验证。

`DeviceBusWidget::openDeviceRequested(const DeviceProfile&)` → `DeviceForge::openDeviceAt(const DeviceProfile&)` 只做编排：`routeTo` → 切 `toolStack` → **按各页真实具备的能力做选中**（见下表，逐页实测），并写一条**脱敏**日志（设备名 + 协议 + 页名，无凭据）。信号载荷取 `DeviceProfile` 而非 `deviceId`：旧 `ip:port` 胶囊本就没有可用的持久 id，而 `editProfileFor` 已经在用 `fromDeviceInfo` 合成（`cpp:636-645`），复用同一段装配即可，无需第二条通道。

**每页"能不能被选中一台"实测（这条推翻了我上一版的 §5 验收第 3 条）**——全仓 `setDeviceBusWidget` 只有 **2 个**调用点（`DeviceForge.cpp:268` 部署页、`:323` 批量命令页），`selectedDevices()` 的消费方只有部署页：

| 目标页 | 现状 | 「打开这台设备」能做到什么 |
|---|---|---|
| 文件部署（index 0） | 有设备下拉 `m_deviceCombo`，**条目键是 ip 文本**（`:1544`/`:1563` `addItem(d.ip)`），现成的按文本定位路径 `:1483-1488` | 切页 **+ 把下拉切到 `Route.ip`**（这是唯一有"选中这台"语义的页，也是 `Route` 必须携带 ip 的原因） |
| 批量命令（index 1，Telnet） | 该页对总线的用法只有 `allDevices()`（`TelnetWidget.cpp:252`）+ `user()/password()`（`:307-308`），**没有"当前设备"概念**（全量 grep `m_deviceCombo|selectedDevices` 零命中） | **只切页**。不得为了凑"选中"去改 Telnet 的目标集语义——那会把"对该 ip 打开"误伤成"只对这一台发命令"，与 §2.4 硬线冲突 |
| MODBUS（index 3） | **未接设备总线**（`ModbusWidget.cpp` 全量 grep `setDeviceBusWidget|selectedDevices|allDevices|deviceSelectionChanged` **0 命中**），它用自己的 `ModbusTargetListModel` + registry | **只切页**。"把这台设备变成一条轮询目标"属子项目 C 的范围，本版不做 |
| OPC UA（index 5） | 端点协议存不出来（见上方边界） | 不可达分支 |

### 2.3 UI 装配（`DeviceBusWidget` 第 1 行）

- 外层：**横向 `QScrollArea`**，`setWidgetResizable(true)`（内部容器宽度由 `QHBoxLayout` 的 `sizeHint` 决定，`false` 要手工同步 inner widget 尺寸，是给自己造第二条真源；此处订正初稿写的 `false`）、竖向 `AlwaysOff`、水平 `AlwaysOff` + `viewport` 滚轮事件转水平滚动（`horizontalScrollBar()->setValue(...)`，`DeviceBusWidget` 已有 `eventFilter` 覆写点，扩一个分支即可，不新增子类）；内层容器仍是 `QHBoxLayout`（分段容器）。
- **胶囊交互（本版唯一的手势改动，用户 2026-10-20 批准甲＋乙）**：左键单击＝切换选中（**不变**）；双击＝**打开这台设备**（`eventFilter` 里现有的 `editProfileFor` 分支改发射 `openDeviceRequested(profile)`）；右键菜单三项**按此次序**＝「打开这台设备 ／ 编辑档案 ／ 移除设备」。置顶项是这次语义变更的**自解释器**——老用户双击发现行为变了，右键一看就知道新含义叫什么、老含义搬去了哪；只做右键不做双击的话新能力会长期无人使用。编辑档案退到第二项但**能力零丢失**（`cpp:589-591` 的显示门槛是 `m_registry` 而非 `deviceId`，生产里 `DeviceForge.cpp:90` 恒注入非空，旧 `ip:port` 胶囊也照样有该项）。
- 段头：`QPushButton`（`objectName="deviceTagHeader"`，`deviceTag` 属性=标签串），文本 `标签名 n/m ▾/▸`；左键＝切折叠；右键菜单＝「本段全选 / 本段反选 / 全部折叠」。
- **折叠与过滤只改胶囊可见性（`setVisible(false)`），绝不少挂**：`selectedDevices()`/`selectedDeviceProfiles()` 按 `m_devices[i]` ↔ `m_pills[i]` **位置配对**（`cpp:796-823`），而宿主把"空选中"解释为「全部设备」（`refreshFromRegistry` 头注 `cpp:515-517` 原文）。少挂成员胶囊会同时打断配对并**静默放大部署目标集**，是事故不是优化。
- 搜索：行尾常驻 `QLineEdit`（`objectName="deviceSearchEdit"`，占位「搜索 名称 / IP / 标签」），实时过滤、**不持久化**（会话态，重启后为空）。
- 重建走 `blockSignals(true)` 窗口 + 末尾一次性 `emit deviceSelectionChanged()`（与波3 编辑器批量刷表同法；「本段全选」也只广播一次）。
- 样式：段头与胶囊只用纯色 + 1px 边框，色值取自 `darkstyle.qss` / `darkstyle-light.qss` 现有 token（石墨边、琴色只用于信号态），双主题各加一节；QSS 不支持渐变与阴影，不得在稿里承诺。

### 2.4 契约保持不变（硬线）

`selectedDevices()`、`selectedDeviceProfiles()`、**`allDevices()`**、**`user()` / `password()`**、`deviceSelectionChanged()`、`deviceProfileEdited()` 的签名与语义一字不改；本版只**新增**一个信号 `openDeviceRequested(const DeviceProfile&)`（纯加法，声明加在类末尾）。选中集合按 `deviceId` **去重**（多段重复显示不影响集合）。三个消费方零改动——注意 Telnet 走 `allDevices()`（与选中态无关），过滤/折叠**绝不能**改变它返回的集合内容。刷新路径仍须保住已选集合（v2.14 Important-4 的语义不得退化）。

### 2.5 持久化

ConfigStore（**禁** QSettings）：仅新增 `device.bus.collapsedTags`（QStringList，缺键＝全展开）。搜索串不持久化。

## 3. 异常态（逐条定死）

1. 旧 `ip:port` 无档案行：进「未分组」；双击＝按合成档案的单端点路由（协议列为空则 ftp 兜底，§2.2）；右键菜单三项**照常齐全**——「编辑档案」的显示门槛是 `m_registry` 判空（`cpp:589-591`）而非 `deviceId`，生产恒非空（`DeviceForge.cpp:90`），编辑走 `cpp:636-645` 现成的 `fromDeviceInfo` 合成路径。**已核实：双击让位不丢任何编辑能力**（我上一版把这里写成"评审必查项：可能造成无处可及"，前提不成立，降级为一条回归用例：旧行胶囊右键「编辑档案」必须仍然可达并保存成功）。
2. 标签含首尾空格 / 空串 / 纯分隔符：`normalizeTag` 后为空即不算标签 → 落「未分组」。
3. 大小写不同标签（`车间A` / `车间a`）：两个段，不合并。
4. 搜索无命中：段头区显示一行提示「无匹配设备（N 台已隐藏）」，**既有选择绝不清空**。
5. 折叠态含已删标签：加载时丢弃（§2.1 规则 4）。
6. 80 台 × 平均 2 标签（约 6 段）：重建必须一次批量挂载，禁止逐行回调（用"批窗口内信号计数为 0 + 段头一次刷新"钉死；**不承诺 wall-clock 毫秒数**——本机测不稳的指标不写进验收）。
7. 目标页尚未创建/懒建（任务中心、设置）：`openDeviceAt` 只走导航已注册的页；`Page::None` 见 §2.2。
8. 日志脱敏：只记设备名/协议/页名/计数，不记凭据与端点口令。

## 4. `normalizeTag` 单源化（含一项必须显性交代的行为变更）

**实测后收窄的改动点**（本条初稿写"读写两侧 + 保存切分 + 圈选四处全部改用 `normalizeTag`"，取证后发现其中三处**现状已经在做等价 trim**，真改动只有一处）：

| 站点 | 现状（实读） | 本版动作 | 是否用户可见 |
|---|---|---|---|
| `DeviceRegistry::normalize`（`src/device/DeviceRegistry.cpp:111-113`，作用于 `upsert:161` / `saveReplacing:195`） | 已 `trim(tag)` + `appendUnique`（`:67-71` 要求 `!value.empty()`）⇒ 档案标签**存库前就去了首尾空白、空串已被丢弃** | 把 `trim` 换成 `devicebus::normalizeTag`——**行为等值的单源化**，不多不少 | 否 |
| 档案对话框标签切分（`src/ui/DeviceBusWidget.cpp:200-204`，`m_tagsEdit` 逗号切分） | 已 `tag.trimmed()` 且跳空 | 同上换调用，等值 | 否 |
| `DeviceProfileCodec` 读侧（`src/device/DeviceProfileCodec.cpp:67-68`） | **不 trim**（原样入 `profile.tags`） | **不改**：库里数据是写入时 normalize 过的；在读侧再改一次等于造第二条真源、还会让"读到的"和"存的"不一致 | 否 |
| 模板圈选（`TaskCenterWidget::resolveTargets` `src/task/TaskCenterWidget.cpp:390-398`，`std::find` 精确相等） | `task.tagSelectors` 取自模板 JSON，**从未 trim** | **唯一真改动**：比较前对 selector 与 `profile.tags` 两侧都 `normalizeTag` | **是**（见下） |

- 范围刻意收窄：**只去首尾空白、只把空串剔除**。不改大小写、不折叠内部空格、不做全半角转换——避免"顺手优化"改变匹配语义。
- 后果（仅此一条）：形如 `" 车间A "` 的**模板 selector** 过去匹配不上，今后匹配得上 ⇒ **某些既有模板的实际部署目标集可能变大**。这是"从漏到不漏"，但属现场可见变更，必须：① 红测钉住该行为（不是意外后果）；② 写进 v2.16 发布说明；③ 手册标签小节补一句口径说明。
- 按新判据这仍属 **MINOR**（无需用户改配置），不升 MAJOR。

## 8. 不做清单（明示 YAGNI）

- 设备级连接状态、心跳、在线检测（"真会话"）——本次双击只是导航入口。**就实一句**：这条线在仓里已经是"有钩子、无数据源"的形态——`DeviceBusWidget::setOnlineStatus(ip, online)`（`cpp:831-841`）**全仓零调用方**（`grep -rn setOnlineStatus src/ tests/` 只有声明与定义两条命中），胶囊的 `online` 属性除该函数外无人设置，于是两套 QSS 的 `#devicePill[online="true"/"false"]` 左边框规则（`darkstyle.qss:676-677` / `darkstyle-light.qss:676-677`）**当前永不命中**。本规格不去接它（没有可靠的在线数据源，接了就是假信号），但视觉稿不得画上线状态色条，手册也不得写"设备栏显示在线/离线"。
- 可保存的"选择集/设备方案"（与 `tagSelectors` 能力重叠）。
- **同一设备多枚胶囊的选中态联动**：多标签设备在 N 个段各显示一枚胶囊，点其中一枚只改那一枚的外观（本版接受，代价是"看着不同步"）；正确性由 §2.4 的**选中集合按设备去重**兜住——执行目标集绝不会因重复显示而部署两次，这条必须有用例钉住（重复点两台不同胶囊＝2 台，重复点同一台的两次显示＝仍是 1 台）。
- 左侧常驻树面板（吃掉横向空间，与 v2.15 窄屏成果冲突）。
- 多级层级文件夹、拖拽设备入组、跨机器/车间树。
- 设备量 >300 的虚拟化/懒加载（按 30–80 台设计，超出的形态另立版本）。
- OPC UA 纳入统一设备/凭据体系（**子项目 C**，复用本规格的分组口径，单独走规格）。
