# DeviceForge 白皮书

**工业级系统部署调试工具**
版本：2.7.0 | 日期：2026-08-18 | 状态：草案

---

## 1. 产品概述

DeviceForge 是一款基于 Qt 6 + C++17 的 **工业级系统部署调试工具**，面向 PLC、嵌入式终端、网络设备等工业硬件的批量部署与运维场景。

它解决的核心问题是：**工业设备的多台批量操作**——一套固件同时部署到 5 台、10 台甚至更多设备，传统工具只能一台一台手动操作，效率低且易出错。

原名 DeployMaster，2026-07-05 更名为 DeviceForge。开源发布（MIT License）。

## 2. 行业背景与痛点

### 2.1 工业现场的现实

工业设备（PLC、嵌入式终端、网关）的运维有一个共同特征：**设备多、协议杂、环境受限**。

- 一条产线可能有几十台同型号设备，升级固件需要逐台操作
- 设备协议五花八门：FTP、Telnet、Modbus、OPC UA、WebSocket……
- 现场网络环境复杂，嵌入式设备的 FTP/SSH 实现往往不标准
- 工程师需要在多个工具之间切换（FileZilla 传文件、SecureCRT 敲命令、Modbus Poll 读寄存器……）

### 2.2 现有工具的不足

| 工具 | 擅长的 | 不足 |
|------|--------|------|
| FileZilla / WinSCP | 单设备文件传输 | 只能一对一，无法批量部署 |
| Total Commander | 本地/远程文件管理 | FTP 插件只能一对一，无批量能力 |
| SecureCRT / Xshell | 单设备命令交互 | 无法批量执行，需要脚本化 |
| Modbus Poll | 单从站调试 | 单点操作，无法集群测试 |

**共同缺陷：没有一个是"为多设备批量运维"设计的。**

### 2.3 机会

DeviceForge 的切入点：**把工业运维中最常见的操作（部署、命令、测试）做成多设备批量执行**，并保持与单设备工具同等的交互体验（双栏文件管理器、终端式命令）。

## 3. 目标用户与使用场景

| 用户 | 场景 | 价值 |
|------|------|------|
| 产线工程师 | 固件升级：同一固件部署到 N 台设备 | 一次点击批量部署（逐台执行），日志逐台确认 |
| 现场调试工程师 | 批量配置下发、批量命令执行 | Telnet/SSH 批量命令，认证失败阻断 |
| 测试工程师 | 设备集群测试：Modbus 批量读写、网络中断调试 | 集群测试 + 透明中继抓包 |
| 售后工程师 | 远程设备巡检、日志收集 | FTP 双栏浏览 + 下载，OTA 更新 |

## 4. 核心能力

### 4.1 已实现（v2.7）

| 模块 | 能力 | 协议 |
|------|------|------|
| **文件部署** | 本地↔远程双栏文件管理器、拖拽上传、多设备批量部署（逐台执行）、选择性部署、目录递归删除、远程重命名/新建目录、远程文件精确对比、部署前清空/部署后重启 | FTP/FTPS (libcurl) |
| **SFTP 文件管理** | 列目录/上传/下载/删除/重命名/新建目录、批量部署（IDeployable 统一部署循环，逐台执行） | SFTP (libssh2) |
| **批量命令** | 批量 Shell 命令、Telnet/SSH 切换、认证失败阻断 | Telnet / SSH |
| **WebSocket 通信** | Server/Client 双模式、默认 localhost 绑定、Token 认证 | WebSocket |
| **Modbus 集群测试** | 批量读写寄存器、自动刷新 | Modbus TCP |
| **网络调试中继** | TCP/UDP/组播透明代理、双向流量捕获、Hex+ASCII 实时视图、`.nrec` 录制/回放 | TCP/UDP |
| **OPC UA 客户端** | 批量读/写节点、DataChange 订阅、地址空间浏览 | OPC UA (open62541) |
| **文件面板 UX 收尾**（v2.7） | 面板源选择器（本地/FTP/SFTP 独立浏览 + 工具栏双向联动）、远程列表/连接异步化（慢速/断网目录读取不冻结 UI、连接状态点含 Connecting 态）、系统文件拖入远程面板上传恢复 | FTP/SFTP |

### 4.2 平台能力

- **「琴色是动词」工业仪表盘主题（暗/亮可切换）**：琴色仅标记可操作/活跃状态，结构一律中性，暗/亮双主题设置中即时切换
- **ConfigStore 配置持久化**：设备列表、凭证（DPAPI 加密）、各 Tool 偏好自动恢复
- **统一日志**：所有 Tool 日志路由到底部可折叠全局日志面板
- **OTA 在线更新**：主程序内检查 + 独立进程替换（Updater.exe）
- **可扩展 Tool 架构**：Tool = Backend (ServiceTask) + Widget (QWidget)，新增功能无需修改主窗口

## 5. 技术架构

### 5.1 双层架构

```
Qt Shell (Widget)          Framework Layer           Adapter Layer
─────────────────          ─────────────────         ──────────────
NavBar 导航栏               ToolHost (桥接)          IProtocolAdapter
DeviceBusWidget             ToolRegistry (注册表)      ├─ FtpAdapter
QStackedWidget 工作区        ToolBackend (基类)         ├─ TelnetAdapter
darkstyle.qss / darkstyle-light.qss（双主题）  ToolWidget (基类)          ├─ SshAdapter (SFTP)
      ↕                          ↕                    ├─ OpcUaAdapter
  lwmsgq 消息队列            ServiceManager            └─ ProtocolRegistry
      ↕                          ↕                         ↕
  AppState                   ServiceTask               libcurl / libssh2 / QTcpSocket
```

### 5.2 技术栈

| 组件 | 用途 |
|------|------|
| Qt 6.11.1 (Widgets) | UI + 网络 + Modbus + 配置持久化 |
| libcurl 8.16.0 | FTP/FTPS 文件传输 |
| libssh2 | SSH 命令通道 + SFTP 文件子系统 |
| open62541 v1.5.5 | OPC UA 客户端 |
| SQLite + DPAPI | 配置持久化 + 凭证加密 |
| lwserverbase / lwcommunicate / lwlog / lwmsgq | 服务框架 / 网络 / 日志 / 消息队列 |

### 5.3 针对嵌入式设备的适配（SylixOS 经验）

SylixOS 自带 FTP 服务器与标准实现有差异，适配经验沉淀为通用能力：

- EPSV 不支持 → 强制 PASV
- `cd()` 只支持单级路径 → MULTICWD 逐级进入
- LIST 不返回 `.`/`..` → 客户端补充导航
- QUOTE 命令 curl RETR 预检误报 → 根 URL + 绝对路径

这些适配对**所有非标准嵌入式 FTP 服务器**都有参考价值。

## 7. 安全与可靠性

- **FTPS 加密传输**：FTP over TLS，防止凭证和文件被窃听
- **libcurl 协议白名单**：仅允许 ftp/ftps
- **凭证 DPAPI 加密存储**：密码不落明文（Windows）
- **日志去敏感化**：Telnet/WebSocket 消息仅记录字节数，不含内容
- **SSH TOFU 主机密钥校验**：防中间人攻击
- **重命名路径穿越校验**：拒绝 `/` 和 `..`
- **部署取消**：传输中可中止（进度回调中断机制）
