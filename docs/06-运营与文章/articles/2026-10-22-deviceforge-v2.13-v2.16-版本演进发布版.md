# 把"隐性语义"一条条揪出来：DeviceForge v2.13—v2.16 完整演进

项目地址：https://github.com/turnarond/DeviceForge

上一篇写到 v2.12——设备档案、任务中心、三大界面重构。这四年……不，这四个版本（v2.13、v2.14、v2.15、v2.16）想解决的是另一类问题：**工具没有报错，但它替你做了你没打算做的事**。

这类问题在工业现场特别隐蔽。程序崩了你会重启，可"没勾选设备时点部署＝对全部设备部署"这种事，它不崩、不报错、日志里还写得挺漂亮，直到某台不该动的 PLC 被刷了一遍。这四个版本里我们干得最多的，就是把这些藏在默认值、边界和"两处实现各写一套"里的隐性语义，一条条揪到台面上，并且给每一条留下能被机器复查的证据。

---

## v2.13：模板要能离开调它的那台机器

这一版是"轻还债版"，主线是把任务模板从"本机资产"变成"可传递资产"。

**导出/导入单模板 JSON 文件**。一台机器上调好的批量部署模板，U 盘带到另一条产线直接导入。格式是公开契约：魔数 + `formatVersion` 版本闸、严格整数判定，**文件里零凭据秘密值**——密码不会跟着模板跑到别人机器上。

导入同名冲突走「覆盖 / 改名 / 取消」三选，默认改名防误覆盖。这里有个刻意的设计：**悬空的设备引用原样保留**，导入时明示"建好同端点档案后自动接上"。因为档案 ID 由端点身份（协议 + IP + 端口）派生，所以你完全可以先把模板带到现场，再在目标机器上建档——顺序不该成为障碍。

**模板编辑器**补齐了任务中心里的新建/编辑/删除。四类步骤（文件部署 / 批量命令 / 重启 / 恢复检查）的参数表单与执行引擎契约逐字一致，不做"界面松、执行严"那套。删除带默认「否」的确认，历史执行快照不受影响。

另外两个小口子：设备档案保存时检测端点同键（协议+IP+端口），堵住"两台档案其实是同一台机器"导致的部署互踩；编辑器 F4 编码不可表示全文时弹窗明示「用 UTF-8 保存 / 返回编辑」，不再静默换码写盘。

**测试基线：46 个 CTest 目标**，新增模板编解码目标，模板通道与编辑器用例 19 个，包含变异负对照和"新建→执行"全链 e2e。

## v2.14：把承诺兑现，把可见性补上

**部署页「保存为模板」**——当前文件清单、目标目录、勾选设备，加上可选的部署后重启，一键固化成任务模板，在任务中心直接执行。这是 v2.11 规格里承诺过的能力，这一版正式兑现。模板语义聚焦"部署什么到哪"，FTPS/端口/并发这类设备连接配置留在工具层，不混进模板。

**任务中心加固。**参数校验的引擎侧与编辑器侧文案换成**单一来源**（一个新的纯函数头），杜绝两处漂移；引擎异常兜底日志全面脱敏；「从失败阶段重试」被拒时文案能分辨真因（是 32 轮历史上限淘汰，还是活跃运行占用）；设备档案落盘失败做**内存完整回滚**，内存与磁盘不再分叉。

**WebSocket 可见性。**事件流新增**对端列**（Server 模式下区分是哪个客户端），这是现场最容易先问的问题："这条消息是谁发的？"接着补了**方向/主题过滤**（过滤只作用于展示，全量事件仍入表，2000 行上限与丢弃计数不受影响）；Token 认证改成**常量时间比较**并限长 256，防逐字节短路的时序侧信道。

**一处文档纠偏值得说。**v2.12 的发布说明里写过"事件流含对端"，实际是这一版才做的。我们在 v2.14 的发布说明里给旧条目**加了勘误注记归位**，而不是偷偷改掉历史正文——对外文档写错是事实错误，但篡改历史是另一种错误。

**测试基线：49 个目标**（新增模板映射、步骤参数校验、窗口放置三个纯逻辑目标）。

## v2.15：文件夹条目"选中即可部署"，以及两处必须核对的变更

这一版把 v2.12—v2.14 期间陆续留池的条目一次收清，分四波推进。

### 目录条目：三个入口统一口径

部署页、模板编辑器（「添加目录…」）、部署页「保存为模板」三个入口一致：选中目录后按**点击时刻的磁盘实况**递归展开为文件条目，远端**镜像原有目录结构**（所选目录自身名作为相对路径首段；散落选中的普通文件仍扁平直落目标目录）。远端子目录由传输执行器在上传前逐级创建，**不需要先手工建目录**。

单次展开的文件条目总数上限 **5000**，超限**整体拒绝**并给出含实际数与上限的中文提示——不会出现"部署了半份清单"这种最难收拾的状态。不跟随符号链接；空目录不算错误；选中文件系统根目录会被拒绝。

### ⚠ 两项现场可见变更，请先核对再升级

1. **SFTP 单发部署目录的远端落点加深一层。**v2.14 及更早，目录映射是协议不对称的（FTP 落点含顶层目录名 / SFTP 只上传内容、不含目录名）。这一版统一为镜像口径：在 `/apps` 选择 `pkg/` 目录，此前内容直落 `/apps/`，**现在落 `/apps/pkg/`**（FTP 落点不变）。依赖旧 SFTP 落点的脚本或站点请复核目标路径。
2. **旧模板里的目录行不会自动展开。**v2.13/v2.14 已存在且含目录条目的模板，执行时这些行仍按目录行确定性失败（逐条目中文报错，不静默跳过）。需要在编辑器里删掉旧目录行、改用「添加目录…」重新添加。**无自动数据迁移**——我们宁可让操作员看见报错，也不在后台改写他的模板。

### 清单不再被 1000 条隐性截断

`ConfigStore::list()` 默认改为全表读取。此前设备档案清扫/回读、模板清单这些承担"遍历全表"语义的调用点，数据超过 1000 行时会**静默丢尾**——多出来的设备不参与清扫也不报错，你永远不会知道。显式传 limit 的调用方行为逐字不变，分页语义保留。

这条是典型的"隐性语义"：不是崩溃，是**看不见的漏**。现场设备或模板过千之后，此前"看不见的那部分"现在会真的参与工作。

### 部署提速与界面

同一轮内后续文件对已确认存在的祖先目录直接跳过探测。5000 条目 × 目录深 3—4 层的形态下可省约上万次控制往返，慢速 SylixOS FTP 现场收益最大。模板编辑器添加目录改为批量一次刷表（此前逐行回调，接近上限时可感知卡顿）。

**部署页工具栏两行化**：单行布局在 1366/1280 屏会把右侧操作裁掉——操作员看不见「导出报告」和「重试失败设备」。现在第 1 行是连接与执行，第 2 行是选项与结果，工具栏最小宽实测 **1866px → 933px**，代价是多占一行高度（约 34px）。

### 已知问题：我们把它写进发布说明，而不是等现场撞上

SylixOS FTP 的三条约束（逐级 CWD、禁用 EPSV、QUOTE 用根 URL + 绝对路径）在 `FtpAdapter` 里**没有单一来源**：逐级 CWD 只在公共选项函数里设过一次，禁用 EPSV 散在四处行内设置。结果是——上传 / 下载 / 预览读回 / 写回这几条自建选项的命令腿**没有逐级 CWD**，而列目录与改名/删除这几条走公共选项的腿**没有禁用 EPSV**。

**目前没有任何现场失败记录**，所以当时按一致性与可维护性债处理，登记为 GitHub #59 排在 v2.16，并在发布说明里留了口子：如果你在这类设备上遇到下载/列目录/改名删除失败，带上服务端类型反馈到那个票。

（这一版初稿曾把影响面写成"上传腿不受影响"，逐行核码后发现不成立——上传腿同样缺逐级 CWD。已按代码实况订正，历史正文不改写、注记归位。）

**测试基线：52 个目标**；工装有界化（`tst_telnet_timeout` 挂 60 秒超时，负载下的挂起形态从"拖死整轮"降为单目标有界红）；CI 修复（runner 钉 windows-2022，配套工具输出统一钉 UTF-8）。

## v2.16：设备栏改版，以及一条"不踩空"的语义修正

### 第 1 行只显示你选中的设备

以前设备栏把所有设备铺成一横排胶囊，80 台的现场要么溢出、要么靠横向滚动找。这一版改成：**第 1 行只显示已选中的设备（chips），其余设备收进「设备 ▾」分组菜单**——一行一个标签分组，点开子菜单才是该组设备，勾选即选中；组内成员顺序就是档案顺序，没有标签的落进「未分组」排在最后。搜索框在菜单**打开时**现场过滤，不改变任何已选内容。

几个刻意的取舍，写出来供现场核对：

- **chips 只显示名称，不再显示 `ip:port`**。依赖"从设备栏直接读 IP"的作业习惯需要改：改看悬浮 tooltip（逐端点 `协议 ip:port` + 备注）或分组菜单项。重名时才追加 `·ip` 短尾标，名称为空仍回落成地址。
- **溢出折成 `+M 台`**，M 是"因放不下而收起"的台数。数量守恒是硬约束：可见 + M 恒等于已选总数。窗口窄的时候 chips 会先让位，`+M 台` 按钮本身永不折走。
- **`全选可见 N 台` 与 `清空选择` 的作用域刻意不对称**：全选只作用当前过滤可见的项（看不见的没法勾，边界写在标签上），清空则清**全部**已选——清空是逃生门，过滤态下只清"看得见的"会留下一堆看不见的选中项继续当部署目标，那才是事故。所以过滤生效时那一项会自述范围：`清空选择（全部 M 台）`。
- **成员为 0 的分组整组不出现在菜单里**（不是"留着组名让你勾空"）；搜索框一个设备都没命中时，菜单里只有一行不可点的「无匹配设备（N 台）」，底部两项一并撤下——一个勾不了任何东西的弹层没有存在价值。

### 双击 = 打开这台设备

双击一台设备，按它**首个可解析端点**的协议跳到对应工具页：ftp/ftps/sftp → 文件部署页并把设备下拉切到该端点的 IP；telnet/ssh → 批量命令页；modbus → MODBUS 页。

这里有两个诚实的交代：

**第一，后两类页面只有"切页"语义，不存在"选中这台设备"。**批量命令页的目标集恒为全部设备，MODBUS 页走自己的点位模型——我们不会为了让它"看起来选中了"去改动它的目标集。

**第二，这个动作挤掉的是原来的"双击＝打开档案编辑对话框"。**而且实现过程中我们发现一个真问题：如果保留"单击 chips＝移出选择"，那**双击在真实鼠标下永远不可能触发**——第一下点击就把那个胶囊隐藏了，第二下根本落不到已经隐藏的控件上。测试里之所以看起来能双击，是因为测试框架直接往控件里注入一个双击事件，绕过了操作系统的命中测试。

最终定档：**移出选择改点 chips 尾部那个「×」**（它原本只是装饰文本，现在是真的点击目标），单击名称主体不再改变选择，键盘空格/回车仍按移出处理保住可达性，「编辑档案」退到右键菜单第二项，**能力零丢失**。右键菜单按此次序：「打开这台设备 ／ 编辑档案 ／ 移除设备」——把新动作置顶，是为了让老用户右键一看就知道新含义叫什么、老含义搬去了哪。

### ⚠ 未选择设备 = 没有目标

**旧版单发部署有一条隐式语义：没有勾选任何设备时点「部署」＝对全部设备部署。**这一版起该兜底废除：未勾选任何设备时点部署**直接被拒**，日志给「未选择目标设备，请在设备栏选择至少一台」，主按钮在空选中时同步显示「▶ 部署（未选择设备）」。

**如果现场有"开程序直接点部署＝全量刷"的作业流程，升级后会被拒绝。**新路径是：设备栏点「设备 ▾」→ 在分组菜单勾选目标（或「全选可见 N 台」）→ 回到部署页点「▶ 部署到 N 台设备」。

为什么要改：任务模板的执行链**一直是空目标即拒绝**（四处站点都是），于是同一个工具里并存着两套语义——模板不敢不选，单发却会替你全选。这次是消除两套并存，不是新增例外。批量命令页（Telnet/SSH）的目标集恒为全部设备，**不受**本变更影响。

### 标签匹配口径统一（结果集可能变大）

模板里的标签选择器与设备档案标签，匹配前统一做**先去首尾空白再比较**（唯一真源是一个纯函数头）。形如 `" 车间A "` 的模板标签过去**静默匹配不上**、今后匹配得上 ⇒ **相关模板的实际部署目标集可能变大**（从漏到不漏）。大小写与内部空格口径不变（`车间a`、`车间 A` 仍不匹配 `车间A`）。

同一改动带出两条例外，一并交代：

1. **纯分隔符标签**（如 `",,"`、`"/"`）归一后判为空 ⇒ **不再匹配任何设备**。selector 写成这类形态的模板从此圈不到东西。
2. 档案存库侧旧的空白清理是 **ASCII 逐字节口径**，新真源用 `QString::trimmed()` ⇒ **全角空格、不换行空格这类 Unicode 空白过去整串保留、今后去掉**，这类标签的**匹配结果会变宽**（`"　车间A"` 从匹配不上变成匹配得上）。

两条例外都是放宽方向、与本版意图同源，**不需要用户改配置**；但既有模板若因此新纳入了设备，请先跑一次"目标设备预览"复核目标集。

### FTP 三条约束落到一个地方（#59 收口）

上一段说的债在这一版还了：禁用 EPSV 上移进公共选项函数，各条自建选项的命令腿改走同一个装配入口，原先散在各处的四行内重复一并删除。**最终形态是 11 条命令腿全部由一个函数保证三条约束**。

同时加了一个静态守卫脚本（`tools/devtools/ftpguard.py`）：解析 `FtpAdapter.cpp`，凡出现 `curl_easy_init()` 的函数（含只 `perform` 不 `init` 的 `duphandle` 形态）都必须能追到三条约束的来源，缺一即红；**解析不到任何一条腿也算失败**（一个"扫到 0 个对象所以全绿"的守卫比没有守卫更危险）。它挂在既有 CI 的 Python 测试步骤里，改这个文件就会被拦。

诚实边界也写进了工具自己的说明：它证明的是"装配齐全"，**不证明传输语义正确**；真机上跑一次 FTP 下载与目录浏览仍是发版前的必做项。

### 版本语义新规

从 v2.16 起定死三条判据：**MAJOR＝对外契约破坏**（SDK/ABI、磁盘格式不兼容、必须改配置的落点变更；纯内部重构不升 MAJOR），**MINOR＝至少一个有独立验收标准的能力包**，**PATCH＝修复/还债/性能**。同时规定 MINOR 及以上必须把安装包挂成 Release 资产（CI 构建产物只保留 90 天，Release 是永久的）。

定这条不是为了好看。之前出现过"一个按钮也发 MINOR"的情况，结果是版本号无法用来判断风险——看到 MINOR 不知道该不该停下作业流程来核对。以后**MINOR 意味着"有新的独立验收标准"**，PATCH 意味着"行为应当兼容，重点核对已知问题段"。

**测试基线：53 个 CTest 目标**，全量两遍 53/53。

## 工程侧：这四个版本是怎么稳住的

**52 → 53 个测试目标**（v2.13 = 46、v2.14 = 49、v2.15 = 52、v2.16 = 53）。

**单源化。**这一批改动反复在做同一件事：把散落在多处的规则收成一个真源，并在源码里写清楚"哪些站点等值、哪些站点真的改变了结果"。标签口径统一动了四处，其中三处等值、一处放宽——这句话不是修饰，它决定了发布说明该写什么，也决定了你去现场核对时该盯哪个入口。

**几何类断言必须与屏宽/缩放无关。**这条是被咬出来的：顶层窗口 `resize(W, H)` 只是一个**请求**，会被窗口管理器钳到可用屏宽（高 DPI 下 1400 的请求变成 962 的逻辑宽度，CI 的虚拟屏同理），此时按最小宽等比压缩的双栏，**比值断言会假红而产品行为根本没变**。现在这类用例无条件判"序"（谁是扩展主体），把依赖兑现宽度的判据放进条件分支，并把走了哪条分支与实际尺寸一起打印出来——否则"这条断言在 CI 上到底跑没跑"不可考。

**测量值必须现算，不烘焙常量。**「×」命中区的宽度是用控件自己的字体量尾标字宽再加上样式层边距，运行时算。同一个式子在默认样式下量出 22px、在生产样式表下量出 16px（样式表把按钮边距解析成了 0）——**如果我们烘焙过一次数字，后者就是一个永远发现不了的缺陷**。

**可达性证据必须来自与用户相同的输入通道。**上一段那个双击问题给了一堂工程课：测试框架可以绕过操作系统的命中测试直接投递事件，所以"测试全绿"和"用户点得到"是两件事。现在这类用例注入完整事件序列（按下→释放→双击按下→释放），并在序列中途断言控件仍然可见——隐藏的控件真实指针打不到。

**每条新断言都先证明它能红。**改坏一处产品代码、看到指定的那一条用例转红、再复原。这一步会暴露两种问题：用例根本没接上（改了不红），或者断言太宽（怎么改都红）。上一段那个几何守卫还有个精确的能力声明：区宽 −2 像素能杀掉它，**−1 像素杀不动**（算术上就不等），所以不能对外宣称"动一点就红"。

**未闭合的观察不写进基线。**有一条测试在并发轮次里报失败但一个字节都没打印，后续 60 次直跑与 8 遍全量都绿、无崩溃事件、无 dump。我们没有把它登记成"随机失败"，而是写成一条**未闭合观察**并要求此后每一轮全量都附带机器可读的结果留档。分诊结论没落到"产品缺陷"之前，不该落到"这是 flake"。

## 快速上手

从 https://github.com/turnarond/DeviceForge/releases 下载 `DeviceForge-v2.16.0-win64.zip`，解压后运行 `DeviceForge.exe`。

升级前三件事：

1. 核对本文 v2.15 与 v2.16 的 **⚠ 段**——这两段写的都是"你原来的操作方式会失效"的变更。
2. 如果设备或模板数量接近千，注意 v2.15 那条"清单不再被隐性截断"会让此前不参与清扫的条目开始参与。
3. 既有模板若用过带空格的标签 selector，先跑一次"目标设备预览"再上现场。

环境与构建：Windows 10/11 x64，Qt 6.9 及以上（CI 以 6.9.2 为上限口径），VS 2022，CMake 3.16+。仓库根目录 `build.bat` 一键构建，`cd build && ctest -C Release --output-on-failure` 跑全量测试。

### CSDN

标题：`把"隐性语义"一条条揪出来：DeviceForge v2.13—v2.16 完整演进`

摘要：DeviceForge v2.13—v2.16 四个版本的演进记录：任务模板跨机迁移与编辑器、部署页保存为模板、文件夹条目选中即可部署、清单去隐性截断、设备栏只显已选 chips + 标签分组菜单、以及"未选择设备＝没有目标"这条语义修正。工业批量运维工具里最危险的不是崩溃，而是它替你做了你没打算做的事。

### 微信公众号

标题：`四个版本，DeviceForge 在修同一类 bug：工具没报错，但做错了事`

导语：没勾选设备时点部署＝对全部设备部署；清单超过 1000 条时后面的静默丢失；标签里多一个空格就永远匹配不上。这四个版本（v2.13—v2.16）几乎都在干同一件事：把藏在默认值、边界和重复实现里的"隐性语义"揪到台面上，并给每一条留下能被机器复查的证据。

### 知乎

标题：`批量运维工具里最危险的错误，是不报错的那种`

### 掘金

标题：`测试全绿，但真鼠标点不到：一次设备栏改版踩到的三个工程坑`

适合技术读者深入阅读的三个点：① 测试框架注入单个事件会绕过操作系统命中测试，导致"隐藏控件仍能被双击"的假绿，以及可达性证据必须走完整事件序列；② 几何类断言为什么会因窗口宽度被钳制和高 DPI 缩放而假红，怎么写成与屏宽无关的判据；③ 静态守卫为什么必须把"零证据"判成失败，以及"测量值现算不烘焙常量"在一次样式表实测里救回了什么。
