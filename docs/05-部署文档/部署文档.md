# 部署文档

> 对应开发规范第 5 条（部署工具链）与第 16 条（交付阶段）。
> 构建细节见 `构建指南.md`；在线升级机制见 `../04-使用手册/架构设计.md`（OTA 子系统）。

---

## 1. 部署方式总览

| 方式 | 适用场景 | 说明 |
|------|----------|------|
| 开发机源码构建 | 开发 / 调试 | `build.bat` 一键构建；可显式设置 `QT_PREFIX`，未设置时按 `D:\Qt`、`C:\Qt` 探测，产物 `build/Release/DeviceForge.exe` |
| 绿色免安装包（zip） | 现场分发 | 主推方式，解压即用，无需安装器 |
| NSIS 安装包 | **禁止分发/自动化阻塞** | 现有递归卸载语义可能删除用户选定的共享目录；必须由独立 PATCH 完成安全修复后再恢复 |
| 在线升级（OTA） | 存量用户升级 | 主程序查版本清单 → 下载 → `Updater.exe` 独立进程替换，失败自动回滚 |

## 2. 绿色免安装包（zip）

### 组成
```
DeviceForge-vX.Y.Z-win64.zip
├── DeviceForge.exe         主程序
├── Updater.exe             在线升级执行器（纯 Win32，不依赖 Qt）
├── libcurl-x64.dll         运行时依赖
├── libssh2.dll             运行时依赖
├── Qt*.dll                 Qt 运行时（Qt6Core/Gui/Widgets/Network/SerialBus/WebSockets/Sql/Concurrent 等）
└── styles/ 或内置资源      主题 QSS / 图标（随 QRC 编译进 exe）
```

### 前置条件
- 目标机需安装 [VC++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)（已装 VS2022 可跳过）。

### 打包
- 按 `../01-白皮书/版本发布与Tag规范.md` 的打包节点流程执行，打包后必须冒烟。
- `.github/workflows/release-validation.yml` 会执行 `windeployqt` 补齐 Qt DLL 与必需插件，生成绿色 zip，再从全新解压目录在隔离 Qt SDK 的环境中运行 UI 冒烟；工作流只上传 portable zip artifact。
- 该工作流只提供可重复验收入口，不创建 GitHub Release 或 Tag，既有 `v2.8.0` Tag 不变。NSIS 自动化与安装包分发保持阻塞，直到独立 PATCH 替换不安全的递归卸载语义。

## 3. 部署验证（冒烟）

```bash
python tools/devtools/smoke.py build/Release/DeviceForge.exe
```

Python 可使用 PATH 中可实际启动的解释器。若 `python`/`python3`/`py` 命中 WindowsApps 占位入口，使用 `D:\Qt\Tools\mingw1310_64\opt\bin\python3.exe`。Qt 路径同样可配置：调用 `build.bat` 前设置 `QT_PREFIX`，脚本未收到该变量时才按 `D:\Qt`、`C:\Qt` 顺序探测；盘符不是工程约束。

- 校验点：进程成功启动 → 主窗口出现（标题含 `DeviceForge`）→ 正常退出（退出码 0）。
- 冒烟是**发布强制项**（交付评审），已纳入手动发布验收工作流。
- 本地 CTest 的 `tst_dpapi_crypto` 需要正常 Windows 用户 profile；CI 或服务账户失败时保留 Windows 错误码，并在正常用户账户复测。

### 手动发布验收入口

`.github/workflows/release-validation.yml` 仅由 `workflow_dispatch` 启动，依次执行版本检查、Release 构建、20 个 CTest、`windeployqt`、portable zip 打包，以及对全新解压副本的隔离环境 UI 冒烟，最后只上传 portable zip artifact。工作流没有写 Tag 或创建 GitHub Release 的权限与步骤；NSIS 路径按上述安全阻塞处理。

## 4. 在线升级（OTA）

- 流程：主程序 `UpdateChecker` 查询远端版本清单 → 比对当前版本 → 下载更新包 → 退出前拉起 `Updater.exe` → 等待主进程退出 → 备份 → 覆盖 → 失败自动回滚 → 重启新版。
- **部署新版本** = 更新版本清单 JSON（含版本号/portable zip 下载地址/校验值）+ 上传验收通过的绿色 zip 到分发服务器；当前不得上传 NSIS 安装包。

## 5. 现场部署注意事项

- **嵌入式设备（SylixOS）FTP 适配经验**（重要，勿回退）：EPSV 不支持（强制 PASV）、`cd()` 只支持单级路径（MULTICWD 逐级 CWD）、QUOTE 命令用根 URL + 绝对路径、DELE 失败多为文件不存在。详见 `04-使用手册/架构设计.md`。
- **升级前备份配置**：`%APPDATA%/DeviceForge/config.db`（含设备列表与 DPAPI 加密凭据）。
- **网络要求**：FTP/SFTP 部署目标设备需可达；OTA 升级需可访问版本清单服务器。

## 6. 部署故障排查

| 现象 | 排查方向 |
|------|----------|
| 启动报 `0xc0000135`（DLL 缺失） | 缺 Qt DLL 或 VC++ 运行库；用 `dumpbin /dependents` 核对 |
| 双击无反应 | 看 `%APPDATA%/DeviceForge/` 日志；确认 exe 与 DLL 同目录 |
| 升级失败 | 查看 `Updater.exe --log <path>` 日志；确认备份目录可写 |
| 远程设备连不上 | 协议（FTP/SFTP）、端口、被动模式、设备端防火墙 |
