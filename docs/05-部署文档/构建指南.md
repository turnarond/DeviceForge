# DeviceForge 构建指南

## 前置要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Visual Studio 2022 | v17.x | MSVC v143 工具集 |
| Qt | 6.11.1 | msvc2022_64 版本 |
| CMake | 3.22+ | VS2022 自带或 [下载](https://cmake.org/download/) |

## 快速开始

### 方法 1：一键构建脚本（推荐）

```cmd
set QT_PREFIX=D:\Qt\6.11.1\msvc2022_64
build.bat
```

`QT_PREFIX` 可指向任意有效的 Qt 6.11.1 `msvc2022_64` 目录；未显式设置时，脚本按 `D:\Qt`、`C:\Qt` 顺序探测。盘符只是本机示例，不是工程约束。

脚本会自动完成：
1. ✅ 检查 Qt 6.11.1 安装路径
2. ✅ 运行 CMake 配置（生成 VS2022 工程）
3. ✅ 编译 Release 版本
4. ✅ 显示运行路径

### 方法 2：CMake 手动构建

```bash
# 1. 配置（生成 VS2022 工程）
mkdir build
cd build
cmake .. -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="D:\Qt\6.11.1\msvc2022_64"

# 2. 编译 Release
cmake --build . --config Release

# 3. 运行
.\Release\DeviceForge.exe
```

### 方法 3：VS2022 直接打开 CMake 生成的项目

```cmd
start build\DeviceForge.sln
```

在 VS2022 中打开 `build\DeviceForge.sln`，选择 `Release|x64`，按 F5 即可编译调试。

## Qt 路径配置

如果 Qt 安装在其他位置，使用以下任一方式指向实际目录：

**CMake 命令**：
```bash
cmake .. -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH="D:\Qt\6.11.1\msvc2022_64"
```

**build.bat**：调用脚本前显式设置 `QT_PREFIX`，无需编辑脚本：
```batch
set QT_PREFIX=D:\Qt\6.11.1\msvc2022_64
```

## 常见问题

### Qt 路径错误

**错误**：
```
[ERROR] Qt 6.11.1 not found. Set QT_PREFIX to the msvc2022_64 directory.
```

**解决**：
1. 确认实际目录下的 `bin\qmake.exe` 存在
2. 为 `build.bat` 设置 `QT_PREFIX`，或为 CMake 设置 `CMAKE_PREFIX_PATH`

### libcurl DLL 未找到

VS F5 调试时，如果 `libcurl-x64.dll` 不在输出目录，需手动复制：

```cmd
copy lib\libcurl-x64.dll x64\Debug\
```

CMake 构建已通过 `POST_BUILD` 自动复制到输出目录。

### libssh2 未找到（SSH 功能不可用）

SSH 适配器依赖 libssh2（**软依赖**，未找到时仅警告）：

```cmd
dir lib\libssh2*
```

应看到：
- `lib\libssh2.lib`（导入库）
- `lib\libssh2.dll`（运行时 DLL）

如缺失，联系项目维护者或查看 `src/adapter/SshAdapter.cpp` 集成说明。

### 清理构建

```cmd
# 清理 CMake 构建
rmdir /s /q build

# 清理 VS 构建
rmdir /s /q x64

# 清理 VS 临时文件
rmdir /s /q .vs
```

## 测试

```bash
# 从仓库根目录运行全部 20 个测试
ctest --test-dir build -C Release --output-on-failure

# 运行单个测试
.\build\tests\Release\tst_nrec.exe testRoundTrip
```

Python 工具可使用 PATH 中可实际启动的 Python 3。若 `python`/`python3`/`py` 命中 WindowsApps 零字节占位入口，使用本机真实解释器：

```powershell
& 'D:\Qt\Tools\mingw1310_64\opt\bin\python3.exe' -m unittest discover -s tools/tests -v
& 'D:\Qt\Tools\mingw1310_64\opt\bin\python3.exe' tools/devtools/versioncheck.py
```

`tst_dpapi_crypto` 需要正常 Windows 用户 profile。CI 或服务账户若返回 Windows 错误 2/3，应保留原始错误码，并在正常用户账户运行同一二进制复测；隔离账户结果不能直接判为产品缺陷。

## CI 与发布验收

- 日常 CI：`.github/workflows/ci.yml`，在 Windows + Qt 6.9.2 下分别构建 Debug/Release 并运行全部 CTest。
- 手动发布验收：`.github/workflows/release-validation.yml`，执行 Release 构建、CTest 与 `windeployqt`，生成绿色 zip 后解压到全新目录，在清除 Qt SDK 环境污染后对解压副本执行 UI 冒烟，并且只上传 portable zip artifact。
- 发布验收工作流不会创建 GitHub Release 或 Tag，既有 `v2.8.0` Tag 不变。NSIS 自动化与安装包分发因现有递归卸载语义不安全而阻塞，必须由独立 PATCH 修复后恢复。
