# 需求分析

> SDD 流程**阶段 0（需求分析）**的产出目录（见 `00-开发规范/SDD-工程化流程.md`）。
> 每个版本 / 功能的需求文档存放在本目录，命名：`2026-08-21-<标题>.md`。

---

## 需求文档模板

```markdown
# 需求：<标题>

- 版本目标：vX.Y
- 提出人 / 日期：
- 关联 issue：#

## 背景与动机
<为什么做>

## 需求描述（用户视角，可验收）
<做什么，怎么用>

## 边界
- In：<本需求包含>
- Out：<明确不做>

## 验收标准（可测）
1. <标准一>
2. <标准二>

## 优先级
P0 / P1 / P2

## 非功能要求
- 长稳：内存 / 句柄 / 连接要求
- 性能：数量级 / 时延
- 兼容性：SDK ABI / 旧配置数据 / 旧版本互操作
- 安全：凭据 / 加密 / 输入校验
```

## 流程

1. 需求文档按模板填写 → 本目录
2. **需求评审**（范围、优先级、验收标准达成一致）
3. 通过后进入方案设计：`03-设计/方案设计/`（评审门禁，见 `00-开发规范/SDD-工程化流程.md`）

## 需求变更

- 需求变更同样走需求评审；影响设计/计划的，同步修订对应文档并重新评审。
