# v2.9 现场工作台与可靠传输需求

**日期**：2026-09-09 ｜ **状态**：需求评审通过 ｜ **版本目标**：v2.9

## 1. 背景

v2.8 已交付并行批量部署、逐设备进度、部署报告和失败重试，但现场文件操作仍存在三类割裂：双栏上传/下载与批量部署使用不同执行路径；部分网络操作会阻塞界面；断线、取消、覆盖和失败恢复缺少一致语义。同时，应用在首窗出现前同步创建全部 Tool，启动观感偏慢，整体仍像多个功能页拼装，而非可长期驻留的现场工作台。

## 2. 用户目标

1. 双栏上传、双栏下载和批量部署共享可靠、可预测的传输行为。
2. 网络中断时自动恢复；失败后可按文件继续，不重复已成功项。
3. 传输期间界面持续响应，状态、重试、取消和失败原因始终可见。
4. 文件与设备成为稳定工作上下文，专业 Tool 作为工作区按需进入。
5. 应用外壳快速出现，非首屏能力延迟初始化。

## 3. 验收基线

- 所有网络传输离开 GUI 线程；提交任务后 100 ms 内界面恢复响应。
- 同一设备内传输串行，不同设备间按 1–8 的受控并发执行。
- 瞬时故障最多自动重试 2 次；确定性故障立即失败；失败项可手动重试。
- 支持会话内、文件级恢复；成功文件不重复传输。
- 上传、下载默认采用临时文件校验后改名提交；能力不足时显式标记非原子降级。
- 取消在 1 秒内进入终态，或在协议最近的可控检查点退出。
- 进度更新最多每 100 ms 一次；状态切换和终态立即通知。
- 首窗可见时间相对 v2.8 同机基线至少降低 50%；热启动中位数优先达到 500 ms 以内。
- 重复启动、取消、切换设备 100 轮，无 UAF，线程、socket 和文件句柄回到基线。

## 4. 范围

### 4.1 本期包含

- 统一传输任务模型、错误分类、重试、取消、原子交付和结果模型。
- 双栏上传/下载/移动与批量部署接入统一可靠性内核。
- Tool 内可折叠任务抽屉。
- 设备上下文固定、文件工作区默认、其他工作区按需加载并保持状态。
- 启动阶段埋点、首窗优先、协议库和非首屏工作区延迟初始化。
- v2.8 已交付状态与路线图对账。

### 4.2 本期不包含

- 单文件字节级断点续传、跨进程任务恢复、全局 Job Center。
- SCP、Linux 适配、插件化加载、ToolHost 多活跃重构。
- 工作区卸载和运行期内存回收策略。

## 5. 已确认决议

- 双栏上传、下载与批量部署统一，但各自保留业务编排和 UI。
- 恢复范围为应用会话内、文件粒度。
- 瞬时故障自动重试 2 次，确定性故障不自动重试。
- 同一设备串行、不同设备并行。
- 双栏覆盖策略在任务提交前一次选择；批量部署默认原子覆盖。
- 采用 Tool 内任务抽屉，不建设全局任务中心。
- 主窗口采用“固定设备上下文 + 工作区”结构，双栏文件工作区为默认入口。
