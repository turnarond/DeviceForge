# 需求：NetRelayTool 广播抓收 + 录制 + 回灌

- 版本目标：v2.8 候选
- 提出人 / 日期：用户 2026-08-21
- 关联 issue：无（本需求文档为源头）
- 关联设计：`docs/03-设计/方案设计/2026-07-10-组播录制回放设计.md`（组播先行设计，广播为其姊妹能力）

## 背景与动机

NetRelayTool 目前支持 TCP/UDP 透明中继 + 组播（Multicast）抓收/录制/回灌（2026-07-10 已落地）。
现场排查中发现：部分工业设备（雷达、传感器等）使用 **UDP 广播（broadcast）** 推送数据，
而现有工具：
1. 协议下拉**没有「广播」选项**；
2. 输入 `255.255.255.255` 或子网定向广播（如 `192.168.1.255`）会被组播校验**直接拒绝**（"非法组播地址"）。

即：**广播数据当前完全无法抓取/录制**。需要补齐与组播对等的广播能力。

## 需求描述（用户视角）

1. 协议下拉增加「**广播（Broadcast）**」选项；
2. 选择广播后，配置区显示**广播地址 + 端口 + 网卡**（复用组播的网卡下拉）；
3. 点击启动：工具作为**额外接收者**抓收发往该广播地址/端口的数据报，不影响现有广播消费者（零影响）；
4. 抓收数据实时显示在 Hex 视图；可勾选**录制**（`.nrec` 文件）；
5. 可**回灌**：把录制的广播流按原始时序重发回**原广播地址/端口**（默认）或用户指定地址；
6. 回放/中继互斥状态机与现有组播一致；回灌前提示"请确认真实源已离线"。

## 边界

- **In**：IPv4 有限广播（`255.255.255.255`）与子网定向广播（`a.b.c.255`，最后 8 位全 1 的非 D 类地址）
- **Out（本期不做，YAGNI）**：
  - IPv6 组播/广播
  - 二层广播（`FF:FF:FF:FF:FF:FF`，需原始套接字）
  - 广播 → 组播 / 组播 → 广播 跨类型桥接
  - 转单播给指定消费者

## 验收标准（可测）

1. 协议下拉含「广播」选项，选中后「监听地址/端口」隐藏或禁用，目标地址标签正确显示「广播地址」
2. 输入 `255.255.255.255` 或 `192.168.1.255` + 端口可正常启动抓收（不再报"非法组播地址"）；输入非法地址（如 `256.1.1.1`、D 类组播地址）被拒并提示
3. 本机广播发送器往广播地址发包，工具 Hex 视图实时显示；录制文件可读回（protocol=Broadcast）
4. 回灌：把录制的广播流按原时序重发回原广播地址/端口，另一个广播接收器收到与录制一致的数据序列
5. 工具抓收期间，另一个广播消费者仍能正常收包（零影响）
6. 旧 `.nrec` 文件（TCP/UDP/Multicast）仍可正常读取回放（向后兼容）

## 非功能要求

- **长稳**：长时间抓收/回灌无内存/句柄泄漏；停止后 socket 与录制文件正确释放（评审检查单长稳项）
- **多网卡**：支持指定网卡抓收（定向广播）与回灌
- **安全**：地址输入 fail-closed 校验（沿用组播校验风格）；非回环监听警告语义对广播同样适用
- **性能**：抓收高频广播不丢包不卡 UI（沿用 QtConcurrent/缓冲策略，本需求以单线程事件循环为准）
